# 씹덕 기획자 모집용 화면 보드 초안

이 문서는 기획자 모집 시 프로젝트를 빠르게 이해시키기 위한 화면 보드 초안이다. 실제 화면기획서를 완성하는 문서가 아니라, 좌측에는 이미지가 들어갈 영역을 두고 우측에는 해당 기능의 목적과 현재 상태, 정리 포인트를 설명하는 형태로 사용한다.

## 이미지 표기 규칙

이미지는 세 가지로 구분한다.

| 표기 | 의미 | 사용 방식 |
|---|---|---|
| 실제 구현 화면 | 현재 프로젝트에 이미 개발되어 캡처 가능한 화면 | 실제 서비스 화면 캡처 삽입 |
| 현재 구현 화면, 정리 필요 | 기능은 있으나 UX/정보 구조/정책 정리가 필요한 화면 | 실제 화면 캡처 삽입 후 보완 포인트 표시 |
| 외부 참고 예시, 아직 미구현 | 아직 개발되지 않았고 방향 이해를 돕기 위한 레퍼런스 | 참고 사이트 스크린샷 삽입, 구현 화면 아님을 명시 |

외부 참고 이미지를 넣을 때는 반드시 아래 문구를 함께 둔다.

> 외부 참고 예시입니다. 실제 구현 화면이 아니며, 기능 방향을 이해하기 위한 레퍼런스입니다.

## 공통 페이지 틀

각 항목은 아래 틀을 반복한다.

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역]` | 화면명 / 상태 / 목적 / 주요 사용자 행동 / 설명 / 정리 포인트 / 참고 이미지 가이드 |

우측 설명 영역에 들어갈 필드:

- **화면명:** 기능 또는 화면 이름
- **상태:** 구현됨 / 1차 구현 / 정리 중 / 미구현 확장 후보
- **이미지 종류:** 실제 구현 화면 / 현재 구현 화면, 정리 필요 / 외부 참고 예시, 아직 미구현
- **목적:** 이 화면이 서비스에서 하는 역할
- **주요 사용자 행동:** 사용자가 이 화면에서 하는 핵심 행동
- **설명:** 처음 보는 사람이 이해할 수 있는 짧은 설명
- **정리 포인트:** 기획 또는 디자인에서 추가로 다듬을 지점
- **이미지 준비 가이드:** 어떤 캡처 또는 레퍼런스를 넣으면 되는지

## 00. 서비스 전체 구조

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 서비스 전체 구조 다이어그램]` | **화면명:** 서비스 전체 구조<br><br>**상태:** 소개용 구조<br><br>**이미지 종류:** 자체 제작 다이어그램<br><br>**목적:** 처음 보는 사람이 `씹덕`이 어떤 서비스인지 한 번에 이해하게 한다.<br><br>**주요 사용자 행동:** 사용자는 게시판과 피드에서 글을 보고 반응하며, 오시/배지/캐릭터로 자신을 드러내고, 뉴스/일정/알림으로 다시 돌아온다.<br><br>**설명:** `씹덕`은 애니·만화·게임 등 서브컬처 사용자를 위한 커뮤니티 허브다. 기본은 게시판 커뮤니티이고, 그 위에 오시 등록, 활동 배지, 신작 일정, 뉴스, Live2D 캐릭터, 시즌패스, 창작자/굿즈 확장 가능성이 붙는다.<br><br>**정리 포인트:** 1차 출시에서는 커뮤니티 기본 루프를 중심에 두고, 창작자/굿즈/시즌패스/유료화는 확장 후보로 분리한다.<br><br>**이미지 준비 가이드:** `커뮤니티 기반 → 덕질 정체성 → 덕질 허브 → 리텐션/수익화 → 장기 확장` 형태의 간단한 구조도를 넣는다. |

## 01. 홈

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 홈<br><br>**상태:** 정리 필요<br><br>**이미지 종류:** 실제 구현 화면 또는 소개용 더미 구성<br><br>**목적:** 서비스 전체 성격을 처음 보여주고, 주요 기능으로 진입시키는 첫 화면이다.<br><br>**주요 사용자 행동:** 인기 글 확인, 오늘의 소식 확인, 주요 게시판 이동, 로그인/프로필 진입, 알림 확인.<br><br>**설명:** 홈은 개인화된 피드보다 상위 개념의 서비스 입구다. 처음 방문한 사용자도 `씹덕`이 게시판 커뮤니티인지, 덕질 허브인지, 어떤 콘텐츠를 다루는지 빠르게 이해할 수 있어야 한다.<br><br>**정리 포인트:** 홈은 서비스 소개와 탐색 입구 역할에 집중하고, 개인화 콘텐츠는 피드로 분리하는 편이 자연스럽다. 홈에 뉴스, 오늘 일정, 인기글, 추천 게시판을 어느 정도까지 노출할지 정리가 필요하다.<br><br>**이미지 준비 가이드:** 메인 화면이 있으면 실제 캡처를 넣고, 아직 정리 전이면 대표 화면들을 조합한 소개형 목업도 가능하다. |

## 02. 게시판

게시판은 서비스의 기본 대화 단위다. 아래 하위 화면들은 모두 게시판 흐름 안에서 연결된다.

### 2-1. 게시판 목록 / 게시판 홈

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 게시판 목록 / 게시판 홈<br><br>**상태:** 구현됨<br><br>**이미지 종류:** 실제 구현 화면<br><br>**목적:** 사용자가 관심 있는 게시판을 찾고, 각 게시판의 성격과 최근 활동을 파악하게 한다.<br><br>**주요 사용자 행동:** 게시판 탐색, 게시판 진입, 게시판 팔로우, 최근 게시글 확인, 카테고리별 이동.<br><br>**설명:** 게시판은 서비스의 기본 대화 단위다. 애니, 만화, 게임, 자유, 공지, 특정 작품/장르 게시판처럼 주제별로 나뉠 수 있으며, 사용자는 게시판을 팔로우해 피드와 알림으로 이어진다.<br><br>**정리 포인트:** 게시판 카테고리 체계, 게시판 표시 순서, 게시판별 익명 허용 여부, 글쓰기 권한, 개념글 기준, 미디어 허용 여부를 한눈에 이해할 수 있게 정리해야 한다.<br><br>**이미지 준비 가이드:** `/board` 또는 게시판 목록 화면 캡처를 넣는다. 게시판명, 카테고리, 최근 글, 팔로우 상태가 보이는 캡처가 좋다. |

### 2-2. 게시글 목록

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 게시글 목록<br><br>**상태:** 구현됨, 정보 밀도 정리 필요<br><br>**이미지 종류:** 실제 구현 화면<br><br>**목적:** 사용자가 게시판 안에서 읽을 글을 빠르게 고르게 한다.<br><br>**주요 사용자 행동:** 글 목록 탐색, 검색/정렬, 말머리 확인, 개념글 확인, 글 상세 진입, 글쓰기 진입.<br><br>**설명:** 게시글 목록은 커뮤니티 사용성이 가장 많이 드러나는 화면이다. 제목뿐 아니라 작성자 신원, 댓글 수, 추천 수, 조회 수, 말머리, 개념글 여부, 작성 시각이 적절한 밀도로 보여야 한다.<br><br>**정리 포인트:** 정보가 적으면 커뮤니티답지 않고, 너무 많으면 피로해진다. 모바일에서는 제목, 댓글 수, 추천 수, 작성자 신원, 말머리 중 무엇을 우선할지 결정해야 한다.<br><br>**이미지 준비 가이드:** `/board/[slug]` 화면 캡처를 넣는다. 게시글 목록, 정렬, 검색, 글쓰기 버튼이 함께 보이면 좋다. |

### 2-3. 게시글 상세 / 댓글

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 게시글 상세 / 댓글<br><br>**상태:** 구현됨<br><br>**이미지 종류:** 실제 구현 화면<br><br>**목적:** 사용자가 글을 읽고 댓글, 추천, 리액션, 신고/차단 등 커뮤니티 상호작용을 하게 한다.<br><br>**주요 사용자 행동:** 본문 읽기, 댓글 작성, 대댓글 작성, 추천/비추천, 감정 리액션, 신고, 차단, 공유 또는 크로스포스트.<br><br>**설명:** 게시글 상세는 커뮤니티 참여가 실제로 일어나는 화면이다. 본문 가독성, 댓글 입력 편의성, 리액션 위치, 신고/차단 접근성이 중요하다. 익명/비고정닉/고정닉의 표시 방식도 이 화면에서 명확해야 한다.<br><br>**정리 포인트:** 댓글 정렬, 대댓글 깊이, 삭제/숨김 표시, 차단 사용자 댓글 접기, 신고 후 상태 표시, 추천/비추천 정책을 정리해야 한다.<br><br>**이미지 준비 가이드:** `/board/[slug]/[id]` 화면 캡처를 넣는다. 본문, 댓글, 추천/리액션, 신고/차단 UI가 보이는 구성이 좋다. |

### 2-4. 글쓰기 / 에디터

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 글쓰기 / 에디터<br><br>**상태:** 1차 구현, 정리 필요<br><br>**이미지 종류:** 현재 구현 화면, 정리 필요<br><br>**목적:** 사용자가 커뮤니티 글을 빠르게 작성하고 이미지, 영상, 스티커를 삽입할 수 있게 한다.<br><br>**주요 사용자 행동:** 제목 입력, 말머리 선택, 본문 작성, 이미지 삽입, 유튜브 임베드, 스티커 삽입, 임시저장, 게시.<br><br>**설명:** 글쓰기는 커뮤니티 참여의 시작점이다. 일반 게시글 작성은 빠르고 가벼워야 하며, 창작물 업로드처럼 복잡한 기능은 별도 트랙으로 분리하는 것이 좋다.<br><br>**정리 포인트:** 임시저장, 이탈 방지, 미디어 업로드 검수, NSFW 검역 저장소, 스티커 선택 UX, 모바일 글쓰기 흐름을 정리해야 한다.<br><br>**이미지 준비 가이드:** `/board/[slug]/write` 또는 `/feed/write` 화면 캡처를 넣는다. 에디터 툴바와 이미지/스티커 삽입 UI가 보이는 캡처가 좋다. |

## 03. 피드

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 피드<br><br>**상태:** 구현됨, 개인화 구조 정리 필요<br><br>**이미지 종류:** 실제 구현 화면<br><br>**목적:** 사용자가 팔로우한 사용자나 게시판 중심으로 글을 모아 보고, 커뮤니티 활동을 개인화된 흐름으로 소비하게 한다.<br><br>**주요 사용자 행동:** 팔로우 글 확인, 크로스포스트 확인, 필터 전환, 게시글 상세 진입, 피드 글 작성.<br><br>**설명:** 피드는 홈과 다르게 개인화가 중심이다. 사용자가 직접 게시판을 찾아다니지 않아도 관심 있는 사람과 게시판의 글을 모아서 볼 수 있어야 한다. 서비스가 계속 열리게 만드는 재방문 화면이다.<br><br>**정리 포인트:** 유저 글, 게시판 개념글, 전체 피드 탭의 역할을 분리하고, 중복 노출과 크로스포스트 표시 방식을 정리해야 한다. 홈과 피드의 경계를 명확히 하는 것도 중요하다.<br><br>**이미지 준비 가이드:** `/feed` 화면 캡처를 넣는다. 팔로우 기반 필터나 크로스포스트가 보이는 화면이 좋다. |

## 04. 프로필 / 오시 / 배지

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 실제 구현 화면]` | **화면명:** 프로필 / 오시 / 배지<br><br>**상태:** 구현됨, 공개 프로필 구조 정리 필요<br><br>**이미지 종류:** 실제 구현 화면<br><br>**목적:** 사용자가 자신이 어떤 덕후인지 드러내고, 다른 사용자가 팔로우할 이유를 찾게 한다.<br><br>**주요 사용자 행동:** 닉네임/아바타 설정, 대표 캐릭터 선택, 오시 등록, 배지 확인, 팔로우 관리, 공개 프로필 확인.<br><br>**설명:** 일반 커뮤니티의 프로필은 닉네임과 아바타 중심이지만, `씹덕`에서는 오시와 배지가 중요하다. 사용자가 좋아하는 작품/캐릭터를 공개하고, 활동 이력을 배지로 보여주면 관계 형성의 단서가 생긴다.<br><br>**정리 포인트:** 오시 최대 개수, 메인 오시 노출, 배지 우선순위, 공개/비공개 설정, 인증 회원 표시, 오시 기반 추천을 정리해야 한다.<br><br>**이미지 준비 가이드:** `/profile`과 `/user/[handle]` 화면 캡처를 넣는다. 오시 카드와 배지가 보이는 화면이 좋다. |

## 15. 캐릭터 페르소나 챗

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 외부 참고 예시, 아직 미구현]` | **화면명:** 캐릭터 페르소나 챗<br><br>**상태:** 미구현 확장 후보<br><br>**이미지 종류:** 외부 참고 예시, 아직 미구현<br><br>**목적:** 캐릭터와 1:1 대화하거나, 사용자가 만든 페르소나를 공유하고 탐색하는 기능이다.<br><br>**주요 사용자 행동:** 캐릭터 선택, 대화 시작, 페르소나 설명 확인, 대화 기록 보기, 인기 페르소나 탐색, 페르소나 공유.<br><br>**설명:** 이 기능을 메인으로 올리면 서비스 정체성이 `커뮤니티 + 캐릭터 AI`로 바뀐다. 현재 제품 방향은 자유 대화형 챗보다 알림, 브리핑, 글쓰기 보조 같은 목적형 덕질 비서가 우선이다.<br><br>**정리 포인트:** 메인화 여부, 미성년자 캐릭터 안전 정책, 성적 대화 차단, 저작권 캐릭터 사용, 추론 비용, 대화량 제한, 개인정보 기억 정책을 정리해야 한다.<br><br>**이미지 준비 가이드:** Character.AI, 제타, AI 캐릭터 채팅 앱의 캐릭터 목록/대화 화면을 참고할 수 있다. 단, 참고 이미지는 제품 방향 후보일 뿐 현재 구현 범위가 아님을 명시한다. |

## 16. 다국어 / 해외 팬 연결

| 좌측 이미지 영역 | 우측 설명 영역 |
|---|---|
| `[이미지 삽입 영역: 외부 참고 예시, 아직 미구현]` | **화면명:** 다국어 / 해외 팬 연결<br><br>**상태:** 미구현 확장 후보<br><br>**이미지 종류:** 외부 참고 예시, 아직 미구현<br><br>**목적:** 한국어 커뮤니티를 기반으로 일본어/영어권 팬덤 콘텐츠와 사용자를 연결한다.<br><br>**주요 사용자 행동:** 해외 소식 번역 보기, 일본 공식 트윗 한국어 요약 보기, 한국어 글의 번역 보기, 다국어 댓글 교환, 해외 팬과 같은 작품 토론.<br><br>**설명:** 다국어는 단순 번역 버튼이 아니라 운영 범위 확장이다. 번역 품질, 외부 콘텐츠 인용, 저작권, 언어별 신고/모더레이션 역량이 필요하다.<br><br>**정리 포인트:** 번역 대상, 자동/수동 큐레이션, 외부 콘텐츠 인용 범위, 언어별 신고 처리, 언어권별 게시판 분리 여부를 정리해야 한다.<br><br>**이미지 준비 가이드:** 번역 커뮤니티, 글로벌 팬덤 서비스, 해외 뉴스 큐레이션 화면을 참고한다. 외부 콘텐츠 원문을 길게 복제하는 캡처는 피하고, 번역/요약 UX 중심으로 참고한다. |
