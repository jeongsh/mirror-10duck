# 바이럴 성장 기능 우선순위

## 1. 결론

바이럴 기능의 최우선 기준은 데이터 수집이 아니라 **공유성, 논쟁성, 반복 플레이, 유저 초대 동기**다.

따라서 분기 체크리스트처럼 유용하지만 공유 갈등과 반복성이 약한 기능은 후순위로 내리고, 먼저 아래 세 가지를 개발한다.

1. `/play/tier-maker`: 티어표 빌더
2. `/play/race-vote`: 레이스형 인기투표
3. `/play/worldcup`: 월드컵 플랫폼

이 세 기능은 모두 공식 DB의 작품/캐릭터를 "등록"하는 것이 아니라 **후보로 선택/참조**한다. DB에 없는 항목만 "빠진 후보 요청"으로 보낸다.

## 2. 우선순위 기준

| 기준 | 설명 |
|------|------|
| 공유성 | 결과 이미지를 SNS/커뮤니티에 올리고 싶어지는가 |
| 논쟁성 | 다른 유저가 반박하거나 자기 버전을 만들고 싶어지는가 |
| 반복성 | 같은 기능을 다른 주제/후보로 여러 번 할 수 있는가 |
| 초대 동기 | "내 최애 투표해줘", "이 티어표 반박해봐"가 자연스러운가 |
| 제작 난이도 | 완성본 기준으로도 기능을 단계적으로 쌓을 수 있는가 |
| 저작권 리스크 | 이미지/영상 업로드 없이도 1차 버전이 성립하는가 |

이 기준에서는 `분기 애니 체크리스트`보다 `티어표`, `인기투표`, `월드컵`이 우선이다.

## 3. 개발 순서

### 1순위. 티어표 빌더

라우트:

- `/play/tier-maker`

목표:

- 사용자가 캐릭터/작품 후보를 직접 티어에 배치하고 결과 이미지를 공유한다.
- "내 기준"이 강하게 드러나므로 반박과 재생성이 잘 일어난다.

대표 주제:

- 애니 캐릭터 싸움순위 티어표
- 내 기준 최강 캐릭터 티어표
- 이번 분기 신작 기대작 티어표
- 여캐/남캐 취향 티어표
- 빌런력 티어표
- 순애력 티어표
- 멘탈 박살 티어표
- 죽으면 안 됐던 캐릭터 티어표
- 내가 사귀면 인생 망할 캐릭터 티어표

티어 라벨 예시:

- `세계관 파괴`
- `작가가 편애함`
- `공식 치트`
- `팬덤 과대평가`
- `내 마음속 1위`
- `나만 좋아함`
- `죽지 마 제발`
- `작가 멈춰`

핵심 UX:

1. 티어표 템플릿 선택
2. 공식 DB에서 작품/캐릭터 후보 선택
3. 후보를 티어 행에 드래그 배치
4. 행 이름/색상 커스터마이징
5. 결과 이미지 저장/공유
6. `이 티어표 반박하기`로 복사 생성

완성본 요구:

- 공식 캐릭터/작품 후보 검색
- 커스텀 후보 추가
- 행 추가/삭제/이름 변경
- 결과 이미지 저장
- 공유 링크
- 기존 티어표 복사해서 내 버전 만들기
- 빠진 후보 요청
- 부적절 후보/이미지 신고

바이럴 포인트:

- 결과물 한 장이 곧 논쟁거리다.
- "반박하기" CTA가 재생성을 만든다.
- 월드컵보다 짧은 시간에 결과를 만들 수 있다.

### 2순위. 레이스형 인기투표

라우트:

- `/play/race-vote`

목표:

- 단순 인기투표를 캐릭터들이 달리는 레이스처럼 연출한다.
- 사용자가 "내 최애 투표해줘"라고 외부에 공유하게 만든다.

대표 주제:

- 이번 주 최애 레이스
- 2026 여름 신작 히로인 더비
- 최강 캐릭터 배틀 레이스
- 빌런 인기 그랑프리
- 내 작품 최애 쟁탈전
- 명대사 결승 레이스

핵심 UX:

1. 투표방 선택
2. 후보 카드 확인
3. 1인 1표 또는 매일 1표 투표
4. 득표 수에 따라 트랙 위치가 실시간 변경
5. 결과/중간 순위 공유
6. 투표 종료 후 우승 연출 표시

오타쿠식 결과 표현:

- `압도적 선두`
- `최종 코너 역전`
- `라스트 스퍼트`
- `사진 판독 중`
- `출발 게이트에서 잠듦`
- `팬덤 화력 부족`
- `오늘의 역주행`
- `운영진도 예상 못한 1위`

완성본 요구:

- 공식 투표방과 유저 생성 투표방 분리
- 투표 기간 설정
- 후보 DB 참조
- 커스텀 후보 제한
- 실시간 또는 준실시간 순위 표시
- 부정 투표 방지
- 결과 이미지/중간 순위 이미지 공유
- 투표 종료 후 아카이브
- 신고/숨김/검수

바이럴 포인트:

- "내 최애 밀어줘" 공유 동기가 강하다.
- 투표 기간 동안 재방문이 발생한다.
- 중간 순위 변화 자체가 콘텐츠가 된다.

### 3순위. 월드컵 플랫폼

라우트:

- `/play/worldcup`

목표:

- 캐릭터, 작품, 명대사, 명장면, OP/ED, 밈 등 다양한 후보로 토너먼트를 만들고 플레이한다.

월드컵 종류:

- 최애 캐릭터 월드컵
- 작품 월드컵
- 명대사 월드컵
- 명장면 월드컵
- 오프닝/엔딩 월드컵
- 커플링/조합 월드컵
- 밈짤 월드컵
- 유저 커스텀 월드컵

핵심 UX:

1. 월드컵 선택
2. 16강/32강/64강 시작
3. 두 후보 중 하나 선택
4. 결승까지 진행
5. 우승/준우승 결과 표시
6. 결과 이미지 공유
7. 내 결과 기반 취향 태그 표시

결과 표현 예시:

- 우승: `최종 생존 최애`
- 준우승: `결승에서 산화`
- 4강 탈락: `여기서 떨어질 애가 아닌데`
- 1라운드 탈락: `팬덤 재판 필요`
- 패배 후보 묘비 연출
- 우승 후보 왕관/트로피 연출

완성본 요구:

- 공식 월드컵과 유저 월드컵 분리
- 후보 타입 일반화
- 공식 DB 후보 선택
- 직접 후보 만들기
- 이미지 후보
- 유튜브 링크 후보
- 텍스트/명대사 후보
- 링크 공개/전체 공개/검수
- 신고/숨김
- 결과 공유 이미지
- 기존 월드컵 복사 생성

바이럴 포인트:

- 플레이 시간이 길고 몰입도가 높다.
- 결과가 강한 자기표현이 된다.
- 명대사/명장면까지 확장하면 콘텐츠 폭이 넓다.

## 4. 후보와 DB 역할 분리

월드컵, 티어표, 인기투표에서 공식 DB 항목을 다시 등록하지 않는다.

| 개념 | 의미 | 액션 |
------|------|------|
| 공식 작품/캐릭터 DB | 서비스가 관리하는 원본 데이터 | 등록/수정/검수 |
| 바이럴 후보 | 특정 티어표/투표/월드컵에 쓰는 참가 항목 | 후보로 추가/제외 |
| 커스텀 후보 | 월드컵/티어표 안에서만 쓰는 임시 항목 | 직접 만들기 |
| 빠진 후보 요청 | DB에 없는 작품/캐릭터 제보 | 검수 요청 |

사용자-facing 용어:

- `DB에서 후보 가져오기`
- `후보로 추가`
- `직접 후보 만들기`
- `빠진 후보 요청`
- `이 후보 정보가 이상해요`

피해야 할 용어:

- `작품 등록`
- `캐릭터 등록`
- `최애 등록`
- `DB 등록`

이 용어는 관리자 화면, 공식 작품/캐릭터 관리, 프로필 오시 등록에서만 사용한다.

## 5. 후보 타입

공통 후보 타입:

- `official_character`: 공식 캐릭터 참조
- `official_work`: 공식 작품 참조
- `release_item`: 분기 신작/릴리즈 참조
- `quote`: 명대사 텍스트
- `scene_image`: 명장면/밈 이미지
- `youtube`: 유튜브 영상 구간
- `custom_text`: 텍스트 후보
- `pair`: 캐릭터 조합/CP/콤비

운영 원칙:

- 공식 DB 후보는 원본 ID를 참조하고 표시명/이미지는 스냅샷을 저장한다.
- 이미지/유튜브 후보는 공식 작품/캐릭터 DB에 넣지 않는다.
- 명대사/명장면은 월드컵/티어표/투표 전용 후보 콘텐츠로 관리한다.
- 전체 공개 콘텐츠는 신고/숨김/검수 상태를 가져야 한다.

## 6. 유저 업로드 정책

### 유튜브

- 영상 파일 업로드는 허용하지 않는다.
- YouTube URL 임베드만 허용한다.
- `video_id`, `start_seconds`, `end_seconds`를 저장한다.
- 썸네일은 YouTube 썸네일을 사용한다.
- 삭제/비공개 영상은 후보 비활성화한다.

### 이미지

- 이미지 업로드는 허용하되 상태를 둔다.
- 상태: `PENDING_REVIEW`, `PUBLIC`, `HIDDEN`, `REJECTED`, `AUTO_BLOCKED`
- NSFW/CSAM 위험 검수 파이프라인과 신고 플로우가 필요하다.
- 출처/권리 고지 체크를 받는다.
- 전체 공개 노출은 검수 후 허용한다.

## 7. 분기 체크리스트 위치 재정의

분기 체크리스트는 바이럴 최우선 기능이 아니다.

의미가 있는 경우:

- 시청 의사 데이터가 알림/추천/회고에 실제로 쓰인다.
- 분기 종료 후 `내 분기 회고`로 재활용된다.
- 시즌마다 자동으로 다시 쓰게 만든다.

의미가 약한 경우:

- 기존 `/season/current` 목록을 다시 보여준다.
- 상태 선택 후 공유 이미지 저장 말고 할 일이 없다.
- 알림/캘린더/추천과 연결되지 않는다.

따라서 바이럴 우선 개발에서는 후순위로 둔다. 기존 분기 페이지 안의 `내 상태 선택`으로 흡수하고, 독립 `/play/season-checklist`는 알림/회고 기능이 준비된 뒤 다시 검토한다.

## 8. 최신 추천 순서

현재 완료/진행 상황:

- 최애 프로필 카드: 완료
- 오타쿠 성향 테스트: 진행 중
- 최애 기반 취향분석: 완료
- 분기 체크리스트: 독립 바이럴로는 우선순위 하향

이미 개발된 최애 프로필 카드, 오타쿠 성향 테스트, 최애 기반 취향분석의 미니게임식 리디자인은 [viral-minigame-polish.md](./viral-minigame-polish.md)를 기준으로 한다.

다음 개발 순서:

1. 티어표 빌더
2. 레이스형 인기투표
3. 월드컵 플랫폼
4. 덕질 연대기
5. 말풍선 밈 생성기
6. 애니 추천 룰렛
7. 분기 체크리스트 고도화

## 9. 구현 전략

### 공통 기반 먼저 만들 것

- 후보 검색 컴포넌트
- 공식 DB 후보 참조 모델
- 커스텀 후보 모델
- 결과 이미지 캡처 컴포넌트
- 공유 링크 저장 구조
- 신고/숨김 상태
- 빠진 후보 요청 폼

### 기능별 차이

| 기능 | 핵심 조작 | 결과물 | 재방문 동기 |
------|----------|--------|-------------|
| 티어표 | 후보를 행에 배치 | 티어표 이미지 | 반박/복사 생성 |
| 레이스형 투표 | 후보에게 투표 | 실시간 순위/레이스 이미지 | 내 최애 투표 독려 |
| 월드컵 | 1:1 선택 반복 | 우승/준우승 이미지 | 재플레이/다른 주제 |

세 기능은 같은 후보 모델과 공유 이미지 시스템을 재사용해야 한다.

## 10. 성공 기준

티어표:

- 결과 이미지 저장률
- 공유 링크 생성률
- 기존 티어표 복사 생성률
- 후보 추가 요청 수

레이스형 투표:

- 투표 참여자 수
- 재방문 투표율
- 중간 순위 공유 수
- 투표 종료 후 결과 공유 수

월드컵:

- 완주율
- 재플레이율
- 유저 생성 월드컵 수
- 결과 공유 수

공통:

- 비로그인 사용자의 기능 완료율
- 공유 링크 유입률
- 빠진 후보 요청/정보 오류 제보 수
- 신고 대비 정상 콘텐츠 비율
