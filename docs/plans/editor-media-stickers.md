# 에디터, 미디어, 스티커 설계

이 문서는 글쓰기, 본문 에디터, 이미지/영상 업로드, 스티커 삽입 작업을 할 때 참고한다. NSFW/아청법 위험 대응은 [nsfw-csam-moderation.md](./nsfw-csam-moderation.md), 게시판 정책은 [community.md](./community.md), DB 확장은 [data-model.md](./data-model.md)를 함께 본다.

## 1. 현재 상태와 목표

현재 에디터는 단순 텍스트 입력과 스티커 토큰 삽입 중심이다. 목표는 디시콘/이미지/영상이 본문에 실제 콘텐츠로 박히는 작성 경험이다.

| 항목 | 현재 상태 | 목표 상태 |
|------|-----------|-----------|
| 에디터 | 단순 입력 위주 | 정식 작성 UX, 첨부, 삽입, 미리보기 |
| 첨부 | 제한적 또는 미연동 | 이미지/영상 업로드, 스토리지 정책, 본문 인라인 삽입 |
| 스티커 | 텍스트 토큰 저장 후 렌더 치환 | 작성 중에도 이미지로 보이고 저장 모델에도 에셋 메타 보존 |

## 2. 콘텐츠 저장 모델

신규 글은 블록 JSON을 권장한다.

```json
{
  "version": 2,
  "blocks": [
    { "type": "paragraph", "text": "본문" },
    { "type": "image", "storageKey": "posts/{postId}/{uuid}.webp", "width": 1200, "height": 800, "alt": "" },
    { "type": "sticker", "stickerId": "uuid", "characterId": "builtin-mao-pro", "emotion": "happy" },
    { "type": "video", "provider": "upload", "storageKey": "posts/{postId}/{uuid}.mp4", "posterKey": "posts/{postId}/{uuid}.webp" }
  ]
}
```

### 마이그레이션 원칙

- 기존 `content text`와 `:sticker/{characterId}/{emotion}:` 토큰은 읽기 렌더러에서 계속 지원한다.
- `content_version`을 추가해 `1 = legacy text`, `2 = block json`으로 구분한다.
- 새 에디터 적용 후에도 과거 글이 깨지지 않아야 한다.

## 3. 작성 UX

- 제목 입력, 말머리 선택, 본문 에디터, 미디어 툴바, 스티커 피커, 미리보기, 임시저장을 제공한다.
- 이미지 드래그 앤 드롭과 클립보드 붙여넣기를 지원한다.
- 업로드 중인 블록은 진행률, 실패, 재시도, 삭제 상태를 보여준다.
- 게시 전 제목 누락, 본문 누락, 업로드 미완료, 금칙어, 게시판 정책 위반을 검증한다.
- 모바일에서는 파일 선택과 카메라 촬영 진입이 자연스러워야 한다.
- 작성 중인 내용이 있으면 페이지 이탈 확인 또는 임시저장으로 보호한다.

## 4. 이미지 첨부

- 지원 포맷은 `jpeg`, `png`, `webp`, 선택적으로 `gif`를 허용한다.
- SVG 업로드는 금지하거나 서버에서 안전한 래스터 이미지로 변환한다.
- 게시판별 파일 수, 총 용량, 개별 용량, 해상도 제한을 설정한다.
- 업로드 직후 원본은 공개 저장소가 아니라 비공개 검역 영역에 저장하고, NSFW/아청법 위험 검수 결과가 `approved`가 된 뒤에만 본문에 노출한다.
- 일반 게시판은 NSFW 이미지가 감지되면 차단 또는 관리자 검수로 보내고, 성인 게시판도 미성년자/연령 불명 성적 콘텐츠 위험이 있으면 전체 차단한다.
- 이미지 검수 결과는 `post_media.moderation_status`와 `moderation_results`에 연결해 작성 API가 승인되지 않은 미디어를 게시하지 못하게 한다.
- 읽기 화면에서는 lazy loading, 반응형 크기, alt 텍스트를 고려한다.
- 삭제된 글의 미디어는 즉시 삭제 또는 보존 기간 후 삭제 정책을 둔다.

## 5. 영상 첨부

- 초기에는 외부 URL 또는 `mp4 H.264` 업로드 중 하나를 선택한다.
- 업로드 영상을 허용할 경우 용량, 길이, 썸네일, 재생 정책을 정한다.
- 자동재생은 기본 금지하고 사용자가 클릭해 재생한다.
- 장기적으로는 트랜스코딩 큐와 HLS를 검토한다.

## 6. 스티커 정책

- 스티커는 사용자에게 토큰 문자열로 보이면 안 된다. 작성 중에도 이미지처럼 보여야 한다.
- 캐릭터를 만들었다고 스티커가 자동 생성되지는 않는다.
- 스티커는 사용자가 직접 이미지 파일을 등록하거나, 사용자가 명시적으로 "AI로 스티커 만들기"를 실행했을 때만 생성된다.
- AI 생성 스티커는 "스티커 만들기" 플로우 안에서만 생성한다. 캐릭터 업로드/구매/거래 직후 자동으로 전체 감정 세트를 만들지 않는다.
- Live2D 표정 지원 여부는 스티커 노출 기준이 아니다. 스티커 피커는 `sticker_assets`에 존재하는 에셋만 보여준다.
- 스티커 라벨은 자유 입력을 허용하되 기본 추천 라벨은 `기본`, `기쁨`, `슬픔`, `놀람`, `응원` 정도로 작게 시작한다. `윙크`, `두근`, `부끄`는 선택 라벨로 둔다.
- 스티커 관리 페이지에서 감정 세트, 삭제, 재생성, 공개/비공개 설정을 제공한다.
- 디시콘형 공용 스티커와 개인 캐릭터 스티커를 모두 수용할 수 있게 `stickers`, `sticker_assets` 테이블을 분리한다.

### 저장 모델 전환 방향

현재 레거시 본문은 `:sticker/{characterId}/{emotion}:` 토큰을 지원한다. 신규 블록 JSON에서는 스티커를 `stickerId` 또는 `stickerAssetId`로 저장한다.

```json
{ "type": "sticker", "stickerId": "uuid", "stickerAssetId": "uuid", "label": "기쁨" }
```

레거시 토큰은 과거 글 렌더링을 위해 유지하되, 신규 작성 UX에서는 사용자가 직접 등록/AI 생성한 스티커 에셋 목록을 이미지 그리드로 고르는 방식을 기준으로 한다.

## 7. 렌더링 원칙

- 게시글, 댓글, 미리보기는 동일 스키마와 동일 렌더러를 사용한다.
- 이미지/영상/스티커 URL은 우리 스토리지 또는 허용 CDN만 렌더링한다.
- HTML 저장 방식을 선택할 경우 strict sanitize가 필수다.
- 긴 글은 후속 최적화로 블록 단위 가상화 또는 접기 기능을 고려한다.
