# 최애 기반 취향분석 기획서

## 1. 결론

`최애 기반 취향분석`은 질문지 테스트가 아니라, 사용자가 고른 최애 캐릭터들의 공식 태그와 유저 투표 태그를 합산해 취향을 리포트로 보여주는 바이럴 기능이다. 라우트는 `/play/oshi-analysis`로 둔다.

핵심 문구:

> 내 최애 10명 넣었더니 취향 들킴

이 기능의 목적은 세 가지다.

- 이미 등록된 작품/캐릭터 DB를 가입 전후 유저가 바로 쓰게 한다.
- 결과 이미지 공유를 통해 외부 유입을 만든다.
- 캐릭터 추가 요청과 태그 수정 제안을 자연스럽게 받아 DB를 유저 참여형으로 보강한다.

## 2. 기존 오타쿠 성향 테스트와의 차이

| 항목 | 오타쿠 성향 테스트 | 최애 기반 취향분석 |
|------|-------------------|-------------------|
| 입력 | 질문에 대한 답변 | 선택한 최애 캐릭터 5~10명 |
| 근거 | 유저가 직접 고른 선택지 | 캐릭터 DB 태그, 포지션, 밈 태그, 유저 투표 |
| 결과 | 유저의 덕질 행동 성향 | 유저가 반복해서 좋아하는 캐릭터상 |
| 출력 | 테스트 유형 1개 중심 | 태그 비율, 공통점, 취향 문장, 추천 캐릭터 |
| 참여 연결 | 결과 공유, 카드 이동 | 캐릭터 추가 요청, 태그 수정 제안, 태그 투표 |

따라서 이 기능은 "또 다른 테스트"로 보이면 안 된다. 화면명과 카피는 `분석`, `리포트`, `취향 폭로`, `최애 조합` 쪽으로 잡는다.

## 3. MVP 범위

### 포함

- 캐릭터 검색 및 선택
- 최소 5명, 최대 10명 선택
- 선택 캐릭터의 `tags`, `meme_tags`, `positions`, `gender`, `work` 정보를 기반으로 점수 계산
- 결과 유형명 생성
- 태그 비율 Top 5 표시
- "당신이 약한 캐릭터상" 문장 생성
- 선택한 최애 목록 표시
- 공유용 결과 이미지 생성
- 캐릭터 추가 요청 CTA
- 태그 수정 제안 CTA

### 제외

- 자유 입력형 캐릭터 생성
- 유저가 만든 분석 공식 공유
- 친구와 궁합 비교
- 랭킹/월드컵 연동
- AI 자유 분석 문장 생성
- 태그 제안 자동 승인

MVP에서는 운영자가 등록한 캐릭터와 승인된 태그만 분석에 반영한다. 유저 제안은 검수 대기 상태로 저장한다.

## 4. 사용자 흐름

### 기본 흐름

1. `/play` 허브에서 `최애 기반 취향분석` 진입
2. 시작 화면에서 설명 확인
3. 작품명 또는 캐릭터명 검색
4. 최애 캐릭터 5~10명 선택
5. 선택 완료 후 분석 실행
6. 결과 화면 표시
7. 결과 이미지 저장 또는 공유
8. 찾는 캐릭터가 없으면 추가 요청
9. 분석이 이상하면 태그 수정 제안

### 가입 전 흐름

- 비로그인 유저도 분석과 이미지 저장은 가능하다.
- 비로그인 유저의 캐릭터 추가 요청은 닉네임/이메일 없이도 임시 제안으로 받을 수 있다.
- 단, 제안 상태 추적과 기여도/배지 지급은 로그인 후 가능하다고 안내한다.

### 가입 후 흐름

- 결과를 프로필에 저장할 수 있다.
- 내 오시 등록 목록에서 바로 분석을 시작할 수 있다.
- 태그 수정 제안 승인 시 기여도 또는 배지를 받을 수 있다.

캐릭터 카드 정보:

- 캐릭터 이미지

- 대표 태그 2~3개

- 캐릭터 이미지가 없는 경우 기본 실루엣을 사용한다.
- 저작권 이미지 이슈가 있으면 공유 이미지에는 작은 썸네일만 쓰거나 캐릭터명을 텍스트 중심으로 표시한다.

### 5.3 분석 중 화면

짧은 연출만 둔다.

- `최애들의 공통점을 캐는 중...`

실제 계산은 클라이언트에서 즉시 가능하므로 0.8~1.2초 정도의 의도적 연출만 둔다.

### 5.4 결과 화면

필수 영역:

- 결과 유형명
- 한 줄 결론
- 태그 비율 Top 5

- 취향 해설 3줄
- 공유 이미지 저장/공유 버튼
- 태그 수정 제안 CTA
- 캐릭터 추가 요청 CTA

예시:

```text
상처 많은 천재캐 수집가

겉으로는 차갑고 강한데,
속은 이미 한 번쯤 무너진 캐릭터에게 약합니다.

취향 구성
- 냉미남 32%
- 천재 21%

- 순애 14%
```

## 6. 결과 구조

### 결과는 1개 타입만 주지 않는다

오타쿠 성향 테스트와 겹치지 않게, 결과는 다음 조합으로 만든다.

- `대표 유형명`
- `태그 비율`
- `취향 문장`
- `선택 최애 공통점`
- `다음에 좋아할 가능성이 높은 캐릭터`

### 결과 유형명 생성 규칙

대표 태그 2~3개를 조합해 유형명을 만든다.

예시:

| 주요 태그 | 결과 유형명 |
----------|-------------|
| 처연 + 천재 + 냉미남 | 상처 많은 천재캐 수집가 |
| 광기 + 빌런 + 순애 | 위험한 순애 빌런 보호자 |
| 성장형 + 열혈 + 주인공 | 주인공 서사 과몰입러 |
| 개그 + 마스코트 + 힐링 | 웃긴 애한테 진심인 사람 |
| 세계관 핵심 + 흑막 + 천재 | 설정 심연 탐사자 |
| 츤데레 + 냉미남 + 순애 | 차가운 순정파 수집가 |

### 결과 문장 톤

좋은 톤:

- 살짝 놀리는 문장
- 캡처해서 공유하고 싶은 문장
- 유저가 "맞네"라고 느끼는 문장

피해야 할 톤:

- 병리화
- 연애/성적 해석 과다
- 특정 성별 비하
- 미성년자 캐릭터와 부적절한 관계 암시
- 너무 진지한 심리검사 문체

## 7. 점수 계산

### 입력 데이터

현재 캐릭터 모델 기준으로 우선 활용할 필드:

- `official_oshi_characters.tags`
- `official_oshi_characters.meme_tags`
- `official_oshi_characters.positions`
- `official_oshi_characters.gender`
- `official_works.genres`
- `official_works.category`

### 기본 산식

캐릭터 1명당 점수를 부여한다.

```text
tags: 각 +3
meme_tags: 각 +2
positions: 각 +1.5
work.genres: 각 +1
work.category: 각 +0.5
```

보정:

- 같은 작품에서 3명 이상 선택하면 해당 작품 장르 점수는 70%만 반영한다.
- 같은 태그가 5명 이상에게서 반복되면 추가 보너스 +3을 준다.
- 선택한 캐릭터 수가 5명일 때는 태그 비율을 보여주되, 추천 정확도 문구는 낮춘다.

### 비율 계산

```text
tag_percent = tag_score / top_5_tag_score_sum * 100
```

표시는 Top 5 합산 기준으로 한다. 전체 태그 합산 기준을 쓰면 소수 태그가 많을 때 비율이 너무 낮아져 공유용 임팩트가 떨어진다.

### 신뢰도

선택 수와 태그 충실도로 계산한다.

```text
base = selected_count / 10
tag_coverage = tagged_character_count / selected_count
confidence = round((base * 0.4 + tag_coverage * 0.6) * 100)
```

문구:

- 80 이상: `분석 신뢰도 높음`
- 50~79: `분석 신뢰도 보통`
- 49 이하: `태그가 부족해서 대충 들켰습니다`

신뢰도가 낮으면 태그 수정 제안 CTA를 더 강하게 노출한다.

## 8. 태그 체계

### MVP 태그 세트

처음부터 태그를 너무 많이 열면 결과가 산만해진다. MVP에서는 운영자가 관리하는 대표 태그 세트를 둔다.

캐릭터 성격:

- 냉미남
- 츤데레
- 광기
- 순애
- 개그
- 힐링
- 멘헤라
- 처연
- 천재
- 노력파
- 열혈
- 무심

서사/역할:

- 주인공
- 조연
- 빌런
- 라이벌
- 흑막
- 세계관 핵심
- 성장형
- 희생캐
- 구원서사
- 멘탈붕괴

팬덤 밈:

- 작가가 굴림
- 죽을수록 매력 있음
- 얼굴은 천사 성격은 재앙
- 설정 과다
- 짤방 제조기
- 공식이 더함

### 태그 표시 규칙

- 캐릭터 선택 카드에는 대표 태그 최대 3개만 표시한다.
- 결과 화면에는 Top 5만 표시한다.
- 상세 태그 목록은 접힌 영역으로 둔다.

## 9. 캐릭터 추가 요청

### 목적

유저에게 DB 입력을 요구하지 않고, "내 분석을 완성하기 위한 행동"으로 보이게 한다.

### 진입 위치

- 검색 결과 없음
- 선택 화면 하단
- 결과 화면 하단
- 공유 이미지 CTA 아래

### 카피

- `내 최애가 없나요?`
- `최애 실종 신고하기`
- `등록되면 다음 분석에 넣을 수 있어요.`

### MVP 입력 항목

- 캐릭터명
- 작품명
- 참고 링크 선택
- 요청 사유 선택

요청 사유:

- `분석에 넣고 싶어요`
- `월드컵 후보로 쓰고 싶어요`
- `카드 만들기에 쓰고 싶어요`
- `작품에는 있는데 캐릭터가 빠졌어요`

### 상태

- `PENDING`: 검수 대기
- `APPROVED`: 등록 완료
- `REJECTED`: 반려
- `MERGED`: 중복 병합

## 10. 태그 수정 제안

### 목적

분석 결과가 이상할 때 유저가 캐릭터 태그를 직접 고치게 한다. 단, 자유 편집이 아니라 선택형 제안으로 시작한다.

### 진입 위치

- 결과 화면의 `분석이 이상한가요?`
- 선택 캐릭터 목록의 각 캐릭터 카드
- 캐릭터 상세 페이지가 생기면 해당 페이지

### UI

```text
이 캐릭터 태그가 이상한가요?

리바이
현재 태그: 냉정 / 강함 / 츤데레

[+] 처연
[+] 먼치킨
[-] 츤데레
[+] 세계관 핵심

[수정 제안 보내기]
```

### 제안 종류

- 태그 추가
- 태그 제거
- 대표 태그 변경
- 이미지 오류
- 이름 오류
- 작품 연결 오류
- 중복 캐릭터

### 반영 정책

- MVP에서는 모든 제안을 관리자 검수 후 반영한다.
- 동일 캐릭터에 같은 태그 제안이 5회 이상 쌓이면 관리자 화면에서 우선 노출한다.
- 승인된 제안은 캐릭터 태그 DB에 반영하고, 제안자에게 기여도 +1을 준다.

## 11. 공유 이미지

### 목적

외부 SNS에서 결과만 봐도 "나도 해보고 싶다"가 떠야 한다.

### 필수 요소

- 서비스 로고 또는 `10duck`
- 결과 유형명
- 한 줄 결론
- 태그 비율 Top 5
- 선택 최애 썸네일 또는 이름 5~10개
- URL 또는 QR 유도 텍스트

### 이미지 문구 예시

```text
내 최애 10명으로 보는 취향 분석

상처 많은 천재캐 수집가
겉은 차갑고 강한데 속은 무너진 캐릭터에게 약함

냉미남 32% · 천재 21% · 처연 18%

10duck에서 내 취향도 들켜보기
```

### 저장 방식

- 최애카드 생성기와 동일하게 클라이언트 캡처 기반 PNG 저장을 우선한다.
- 로그인하지 않아도 이미지 저장 가능.
- 공유 링크 저장은 2차 범위로 둔다.

## 12. 데이터 모델 초안

Supabase 변경은 구현 시 MCP로 직접 적용한다. 기획 단계에서는 모델만 정의한다.

### `character_add_requests`

```sql
create table public.character_add_requests (
  id uuid primary key default gen_random_uuid(),
  requester_id uuid references auth.users(id) on delete set null,
  character_name text not null,
  work_title text not null,
  source_url text,
  reason text not null,
  status text not null default 'PENDING',
  admin_note text,
  decided_by uuid references auth.users(id) on delete set null,
  decided_at timestamptz,
  created_at timestamptz not null default now()
);
```

### `character_tag_suggestions`

```sql
create table public.character_tag_suggestions (
  id uuid primary key default gen_random_uuid(),
  requester_id uuid references auth.users(id) on delete set null,
  official_oshi_character_id uuid not null,
  suggestion_type text not null,
  tag text,
  status text not null default 'PENDING',
  reason text,
  admin_note text,
  decided_by uuid references auth.users(id) on delete set null,
  decided_at timestamptz,
  created_at timestamptz not null default now()
);
```

### `oshi_analysis_results` 2차 범위

MVP에서는 저장하지 않아도 된다. 공유 링크와 프로필 저장을 붙일 때 추가한다.

```sql
create table public.oshi_analysis_results (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) on delete set null,
  result_title text not null,
  result_summary text not null,
  selected_character_ids uuid[] not null,
  tag_scores jsonb not null,
  confidence integer not null,
  expires_at timestamptz,
  created_at timestamptz not null default now()
);
```

## 13. 관리자 기능

MVP 관리자 화면에 필요한 것:

- 캐릭터 추가 요청 목록
- 태그 수정 제안 목록
- 캐릭터별 누적 제안 수
- 승인/반려/중복 병합
- 승인 시 공식 캐릭터 태그 업데이트

운영 우선순위:

1. 많이 요청된 캐릭터
2. 분석 결과에서 자주 선택되는데 태그가 부족한 캐릭터
3. 같은 태그 수정 제안이 반복되는 캐릭터

## 14. 전환 연결

### 최애 카드 생성기 연결

결과 화면에서:

- `이 취향으로 최애 카드 만들기`
- 선택한 대표 최애 1명을 카드 생성기에 넘긴다.
- 결과 유형명을 카드 문구 후보로 넘긴다.

### 프로필 오시 연결

로그인 유저:

- `이 최애 목록을 프로필에 저장`
- 최대 5개만 오시 등록으로 저장 가능하므로, 10명 중 저장할 5명을 고르게 한다.

### 게시판 연결

선택한 캐릭터의 작품이 연결된 게시판이 있으면:

- `같은 최애 얘기하러 가기`
- `이 작품 채널 보기`

게시판 연결이 없으면 후순위로 둔다.

## 17. 리스크와 대응

### 캐릭터 태그 품질이 낮으면 결과가 부정확하다

대응:

- 신뢰도 문구를 보여준다.
- 태그 부족 캐릭터를 운영 우선 보강 대상으로 잡는다.
- 유저 태그 제안을 결과 화면에 자연스럽게 연결한다.

### 오타쿠 성향 테스트와 겹쳐 보일 수 있다

대응:

- 질문을 묻지 않는다.
- 결과를 1개 유형으로만 끝내지 않는다.
- 태그 비율과 선택 캐릭터 공통점을 중심으로 보여준다.

### 캐릭터 이미지 저작권 리스크

대응:

- 공유 이미지에서는 작은 썸네일 또는 텍스트형 목록 옵션을 제공한다.
- 운영자가 등록한 이미지 URL만 사용한다.
- 이미지 없는 캐릭터도 분석 가능하게 한다.

### 태그 논쟁이 과열될 수 있다

대응:

- 태그 수정은 바로 반영하지 않고 제안으로 받는다.
- 캐릭터 평가가 아니라 "분석 정확도 개선"으로 카피를 잡는다.
- 공격적 태그와 비하 태그는 운영 태그 세트에 넣지 않는다.

## 18. 추천 우선순위

지금 바로 개발한다면 1단계와 2단계 일부를 같이 하는 것이 좋다.

필수:

- 캐릭터 선택
- 취향 분석 결과
- 결과 이미지 저장
- 캐릭터 추가 요청
- 태그 수정 제안

후순위:

- 공유 링크 저장
- 프로필 저장
- 친구 궁합
- 월드컵 연결
- AI 문장 생성

이 기능은 단독 바이럴 기능이면서 동시에 캐릭터 DB를 유저 참여형으로 전환하는 첫 관문이다. 사용자는 데이터를 입력하는 것이 아니라 자기 최애 분석을 완성한다고 느껴야 한다.
