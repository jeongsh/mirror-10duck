# 신고, 차단, 운영, 알림 설계

이 문서는 신고, 차단, 운영자 도구, 알림, 레이트 리밋 작업을 할 때 참고한다. NSFW/아청법 위험 대응은 [nsfw-csam-moderation.md](./nsfw-csam-moderation.md), 관련 DB는 [data-model.md](./data-model.md), 커뮤니티 화면 맥락은 [community.md](./community.md)를 함께 본다.

## 1. 운영 기능의 위치

커뮤니티 서비스에서 운영 기능은 후순위 부가 기능이 아니라 출시 안정성의 핵심이다. 글쓰기와 댓글이 가능해지는 순간 신고, 숨김, 삭제, 차단, 제재의 최소 루프도 함께 고려해야 한다.

## 2. 사용자 신고

- 신고 대상은 게시글, 댓글, 프로필, 스티커, 캐릭터 에셋이다.
- 신고 사유는 욕설/혐오, 도배, 음란물, 미성년자/연령 불명 성적 콘텐츠, 불법 가능 콘텐츠, 저작권, 개인정보, 사기/거래 문제, 기타를 제공한다.
- 신고 시 선택 사유와 상세 설명을 저장한다.
- 동일 사용자가 같은 대상에 중복 신고하지 못하게 한다.
- 신고 누적 임계치에 따라 자동 숨김 또는 운영자 검토 대기로 전환한다. 기본값은 서로 다른 사용자 3명 이상 신고 시 자동 숨김이며, 미성년자/연령 불명 성적 콘텐츠나 불법 가능 콘텐츠 사유는 즉시 고우선순위 검수 큐에 넣는다.
- 허위 신고 남용을 추적할 수 있게 신고자 이력도 보존한다.

## 3. 차단

- 사용자는 특정 유저를 차단할 수 있다.
- 차단한 유저의 글/댓글은 기본 접힘 처리한다.
- 차단한 유저에게서 알림을 받지 않는다.
- 차단된 사용자가 내 프로필/글에 상호작용하는 범위를 정책으로 정한다.
- 운영자/관리자 계정은 차단으로 숨기지 않는다.

## 4. 운영자 도구

- 신고 큐를 확인하고 처리 상태를 변경한다.
- 게시글/댓글 숨김, 삭제, 복구, 잠금, 댓글 잠금을 수행한다.
- 유저 경고, 기간 정지, 영구 정지, IP 제한을 수행한다.
- 게시판 공지 등록, 말머리 관리, 개념글 수동 조정, 게시판 규칙 편집을 수행한다.
- 모든 운영 액션은 `moderation_logs`에 남긴다.
- 게시판별 운영자와 전체 관리자 권한을 분리한다.
- 이미지/스티커/캐릭터 에셋 검수 큐에서는 AI 판정 점수, 위험 태그, 해시 중복 이력, 신고 사유, 게시판 성인 여부를 함께 보여준다.
- 고위험 이미지 조치에는 숨김, 삭제, 해시 차단, 사용자 경고/정지, 성인 게시판 이동 권고, 이의제기 처리 상태가 포함되어야 한다.

## 5. 알림 이벤트

- 내 글에 댓글이 달림
- 내 댓글에 답글이 달림
- 내 글이 추천 또는 개념글 등극됨
- 누군가 나를 팔로우함
- 내 글/댓글이 신고 처리됨
- 운영자가 공지 또는 제재 메시지를 보냄
- 팔로우한 게시판에 개념글이 올라옴
- 관심 등록한 신작이 공개되거나 방영/연재/출시를 시작함
- 관심 애니가 오늘 방영됨
- 관심 만화가 오늘 연재되거나 단행본/정발 발매일에 도달함
- 관심 게임의 출시, 업데이트, 점검, 이벤트 일정이 다가옴
- 관심 태그와 일치하는 주요 뉴스가 등록됨
- 신작/방영/연재/출시 일정이 연기, 휴방, 변경됨

## 6. 알림 UX

- GNB에 읽지 않은 알림 카운트를 표시한다.
- 알림 목록 페이지 또는 드롭다운을 제공한다.
- 알림 클릭 시 해당 글/댓글 위치로 이동한다.
- 중요 알림은 Live2D 말풍선과 감정 모션으로 함께 보여준다.
- 알림은 읽음/모두 읽음 처리가 가능해야 한다.
- 차단한 사용자에게서 발생한 알림은 기본적으로 생성하지 않는다.
- 신작/일정 알림은 사용자의 관심 등록과 알림 설정을 따른다.
- 기본 알림은 당일 알림 정도로 가볍게 두고, 30분 전/방영 후 감상 유도/변경 알림은 사용자가 조정하게 한다.
- Live2D 말풍선에는 오늘 방영, 이번 주, 내 관심작, 새 소식 버튼을 제공한다.
- 오늘 방영 애니 알림은 감상글 보기, 글쓰기, 관련 채널 이동으로 이어져야 한다.

## 6-1. 알림 종류 매트릭스 (2026-05-18 확정)

`notifications.type` enum은 아래 8종으로 고정한다. 기존 `COMMENT / REPLY / REACTION / FOLLOW / HOT_PROMOTED / SYSTEM` 6종에 신작/일정 알림용 `RELEASE`와 본문/댓글의 `@handle` 멘션용 `MENTION`을 추가한다. 종류별 채널 노출, 묶기, 사용자 제어 방침은 아래 표를 기준으로 한다.

| type | 대표 트리거 | DB 기록 | 목록 노출 | GNB 배지 | Live2D 말풍선 | 묶기 기본 |
|------|-------------|---------|-----------|----------|---------------|-----------|
| COMMENT | 내 글에 새 댓글 | O | O | O | O | 글 + type + 1시간 |
| REPLY | 내 댓글에 답글 | O | O | O | O | 부모 댓글 + type + 1시간 |
| REACTION | 내 글/댓글에 감정 리액션 또는 추천 | O | O | O | O | 글 + type + 1시간 |
| FOLLOW | 누군가 나를 팔로우 | O | O | O | O | 수신자 + type + 1시간 (count로 누적) |
| MENTION | 글 또는 댓글에서 나를 `@handle`로 멘션 | O | O | O | O | 대상 글/댓글 + type + 1시간 |
| HOT_PROMOTED | 내 글 개념글 등극, 팔로우 게시판 개념글 | O | O | O | O | 글 + type (보통 단발) |
| SYSTEM | 운영 공지, 제재, 신고 처리 결과 | O | O | O | O | 묶지 않음 |
| RELEASE | 관심 신작 공개, 오늘 방영/연재/출시, 일정 변경 | O | O | O | O | release_item + type + 1시간 |

운영 메모:
- "추천"과 "감정 리액션"은 별도 type을 두지 않고 `REACTION` 안에서 sub 타입으로 표시한다.
- "개념글 등극"은 type 분리 없이 `HOT_PROMOTED`로 유지하고, 운영 트리거가 추가되면 우선 `SYSTEM`으로 보낸다.
- `RELEASE`는 관심 신작이 없으면 발생하지 않는다. 관심 신작 알림 시간(30분 전, 당일 등)은 별도 `release_reminder_settings`에서 조정한다.
- `MENTION`은 글/댓글 본문에서 `@handle` 토큰을 파싱해 발행한다. 같은 글 안에서 같은 사용자가 여러 번 멘션되어도 1행으로 묶고 `aggregate_count`만 올린다.
- 차단한 사용자에서 발생한 이벤트는 모든 type에서 알림을 만들지 않는다.

## 6-2. 묶기 정책

같은 대상에 짧은 시간 동안 알림이 쏟아질 때 1행으로 묶어 노이즈를 줄인다.

- 묶기 키(`group_key`)는 `type + 타겟 ID + 윈도우`로 구성한다. 타겟은 글, 댓글, release_item 등 알림이 가리키는 대상이다.
- 윈도우는 **1시간** 단위로 끊는다. 윈도우 안에서 새 이벤트가 들어오면 기존 `notifications` 행을 업데이트해 `aggregate_count`만 +1 한다.
- 윈도우가 지나거나, 사용자가 해당 알림을 읽고 다시 새 이벤트가 들어오면 새 행을 만든다.
- 묶인 알림의 `title` / `content`는 `"새 댓글 N개"` 처럼 count를 반영한 표현을 사용한다.
- `SYSTEM` 알림은 묶지 않는다. 운영 메시지 1건은 항상 1행이다.
- `FOLLOW`도 1시간 윈도우 묶기를 적용해 "오늘 N명이 나를 팔로우했어요" 형식으로 노출한다.

## 6-3. Live2D 말풍선 정책

말풍선은 GNB 카운트와 별개의 표현 채널이고, 끄기 토글이 따로 있다.

- Live2D 말풍선은 7종 type 전부에 대해 띄울 수 있다. 다만 빈도와 쿨다운으로 노이즈를 통제한다.
- **전역 쿨다운 60초** — 마지막 말풍선이 닫힌 시점부터 60초 안에는 새 말풍선을 띄우지 않는다.
- **type별 쿨다운 5분** — 같은 type은 마지막 노출 후 5분 안에는 다시 띄우지 않는다. 그 사이 들어온 알림은 큐에 모았다가 쿨다운이 풀린 뒤 가장 최신 1개만 표시한다.
- 묶기 정책으로 이미 `aggregate_count`가 올라간 행은 말풍선에서도 count를 함께 보여 준다 (`"새 댓글 N개"`).
- 쿨다운 동안 큐에 쌓인 알림은 사라지지 않고, 알림 목록과 GNB 배지에는 즉시 반영된다. 말풍선은 보조 채널이다.
- 사용자가 `Live2D ON/OFF`를 끈 경우 말풍선은 채널 자체가 비활성화된다. 알림 목록과 배지는 그대로 동작한다.

## 6-4. 사용자 알림 설정

설정 화면(`/profile` 안의 알림 탭 또는 `/settings/notifications`)에는 토글 2개만 둔다. 종류별 세분화는 의도적으로 지금 단계에서는 만들지 않는다.

- **전체 알림 받기 (ON/OFF)** — OFF 시 모든 type의 `notifications` INSERT를 막는다. 본인 활동 회신도 만들지 않는다.
- **Live2D 말풍선 받기 (ON/OFF)** — OFF 시 알림은 정상 기록되지만 말풍선만 띄우지 않는다.

저장은 `user_notification_settings` 테이블에 `user_id` 기준으로 두 컬럼만 둔다. 기본값은 둘 다 ON.

향후 종류별 토글이 필요해지면 같은 테이블에 컬럼을 추가하거나 `user_id × type` 매트릭스 테이블로 확장한다. 이번 단계에서는 도입하지 않는다.

## 7. 레이트 리밋과 어뷰징 방지

- 비로그인 작성은 IP/브라우저 단위 제한을 둔다.
- 이미지/영상 업로드는 사용자, IP, 게시판 단위로 분당/일일 제한을 둔다.
- 짧은 시간 반복 댓글, 동일 내용 반복 게시, 과도한 신고를 감지한다.
- 임계치 초과 시 쿨다운, 캡차, 임시 제한, 운영자 검토 중 하나를 적용한다.
