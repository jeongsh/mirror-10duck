# 커뮤니티 제품 설계

이 문서는 게시판, 게시글, 댓글, 추천/비추천, 개념글, 피드, 검색, 프로필/신원, 익명 글쓰기 작업을 할 때 참고한다. 에디터와 미디어는 [editor-media-stickers.md](./editor-media-stickers.md), DB 필드는 [data-model.md](./data-model.md)를 함께 본다.

## 1. 제품이 닮아야 하는 감각

- 디시인사이드/아카라이브처럼 게시판 중심의 빠른 글쓰기, 댓글, 개념글 흐름을 제공한다.
- 트위터식 피드처럼 내가 팔로우한 사람과 게시판의 활동을 모아보는 개인 타임라인을 제공한다.
- 제타/캐릭터 챗 서비스처럼 캐릭터가 단순 장식이 아니라 말풍선, 리액션, 스티커, 장기 기억으로 사용자 경험에 개입한다.
- 마켓플레이스는 처음부터 전면에 세우기보다, 커뮤니티에서 캐릭터 애착과 에셋 수요가 생긴 뒤 자연스럽게 연결한다.

## 2. 게시판/채널

현재 `boards` 테이블과 `/board/[slug]` 라우팅이 존재한다. 목표는 게시판이 단순 카테고리가 아니라 각각의 운영 규칙과 분위기를 가진 독립 공간이 되는 것이다.

| 항목 | 현재 상태 | 목표 상태 |
|------|-----------|-----------|
| 게시판 목록 | `boards` 조회 기반 기본 목록 | 인기 게시판, 팔로우 게시판, 최근 방문, 신규 게시판, 관리자 추천 구역 제공 |
| 게시판 상세 | 글 목록과 팔로우 버튼 중심 | 공지, 탭, 정렬, 검색, 규칙, 관리자, 통계, 글쓰기 진입 제공 |
| 게시판 메타 | `slug`, `name`, `description` | 아이콘, 배너, 주제 태그, 규칙, NSFW 여부, 익명 허용 여부, 첨부 제한, 운영자 목록 |
| 권한 | 인증 사용자 중심 | 공개/회원 전용/승인제, 글쓰기 제한, 댓글 제한, 차단 사용자 제어 |

### 게시판 화면 요구

- 상단에는 게시판 이름, 설명, 팔로우 상태, 글쓰기 버튼, 검색 진입이 있어야 한다.
- 공지글은 일반 글과 분리하거나 목록 상단에 고정한다.
- 목록 정렬은 최신순, 댓글순, 추천순, 조회순, 개념글을 제공한다.
- 게시판별 말머리 또는 탭을 제공한다. 예: 잡담, 질문, 창작, 정보, 거래, 후기.
- 모바일에서는 글 제목, 댓글 수, 추천 수, 작성자, 시간 정보가 한눈에 보여야 한다.

## 3. 게시글

현재 `posts`는 게시판 글과 피드 글을 함께 담는 하이브리드 구조다. 이 방향은 유지하되, 커뮤니티 게시글로서 필요한 지표와 정책 필드를 보강해야 한다.

| 항목 | 현재 상태 | 목표 상태 |
|------|-----------|-----------|
| 본문 | `content text` | `content_version`, 블록 JSON 또는 제한 HTML, 레거시 텍스트 호환 |
| 작성자 | `author_id`, `author_email` | 표시 닉네임, 신원 유형, 아바타, 대표 캐릭터, 작성 시점 스냅샷 |
| 지표 | `is_hot`, `hot_promoted_at` | 조회수, 댓글 수, 추천/비추천 수, 스크랩 수, 신고 수 |
| 상태 | 삭제 중심 | 정상, 숨김, 삭제됨, 관리자 삭제, 신고 대기, 잠금, 댓글 잠금 |
| 분류 | `board_id`, `source_type` | 게시판 탭, 말머리, 태그, 원본/공유 관계 |

### 게시글 상세 화면 요구

- 제목, 게시판, 말머리, 작성자 신원 뱃지, 작성 시간, 수정 시간, 조회수, 추천/비추천, 댓글 수가 보여야 한다.
- 본문은 텍스트, 이미지, 영상, 스티커가 깨지지 않게 렌더링되어야 한다.
- 작성자 영역에는 팔로우, 차단, 작성글 보기, 대표 캐릭터 보기 진입이 있어야 한다.
- 글 하단에는 추천/비추천, 감정 리액션, 스크랩, 공유, 신고, 목록 이동이 있어야 한다.
- 작성자 본인에게는 수정/삭제가 보여야 하고, 운영자에게는 숨김/삭제/잠금/개념글 조정이 보여야 한다.

### 게시글 목록 요구

- 제목 옆에 댓글 수를 노출한다.
- 이미지/영상/스티커 포함 여부를 작은 아이콘으로 표시한다.
- 개념글, 공지, 잠금, 삭제됨, NSFW 상태를 구분한다.
- 작성자 표시에는 닉네임과 신원 뱃지를 함께 보여준다.
- 모바일에서는 과도한 본문 미리보기보다 제목과 지표 가독성을 우선한다.

## 4. 댓글과 대댓글

현재 `comments`는 텍스트 댓글 또는 스티커-only 댓글을 지원한다. 커뮤니티 사이트로 보이려면 댓글은 단순 입력창이 아니라 대화 흐름과 운영 정책을 품어야 한다.

| 항목 | 현재 상태 | 목표 상태 |
|------|-----------|-----------|
| 댓글 | 텍스트 또는 스티커-only | 텍스트, 스티커, 이미지 선택 지원, 수정/삭제, 신고 |
| 대댓글 | 없음 | 1단계 대댓글 또는 답글 참조 지원 |
| 작성자 | `author_id`, `author_email` | 닉네임 스냅샷, 신원 뱃지, 대표 캐릭터 스냅샷 |
| 정렬 | 작성순 | 작성순, 인기순, 내가 쓴 댓글 강조 |
| 상태 | 본인 삭제 | 관리자 숨김, 신고 누적 숨김, 차단 사용자 댓글 접기 |

### 댓글 UX 요구

- 댓글 입력창은 게시글 하단에 고정적으로 접근 가능해야 한다.
- 스티커 피커는 댓글에서도 동일하게 사용한다.
- 댓글마다 추천/비추천 또는 감정 리액션을 제공할지 정책을 정한다. 권장: 댓글은 가벼운 추천/비추천, 게시글은 감정 리액션까지 제공.
- 대댓글은 무한 중첩이 아니라 1단계만 허용해 모바일 가독성을 지킨다.
- 삭제된 댓글은 대화 맥락 보존을 위해 "삭제된 댓글입니다"로 남길지, 완전히 제거할지 정책을 정한다.

## 5. 추천, 비추천, 개념글

현재 개념글은 디버그 토글에 가깝다. 목표는 커뮤니티 참여 신호를 기반으로 자동/수동 개념글 시스템을 갖추는 것이다.

### 추천 시스템 요구

- 게시글 추천/비추천은 감정 리액션과 별도 축으로 둔다.
- 한 사용자당 한 글에 추천 또는 비추천 하나만 허용한다.
- 추천 취소, 비추천 취소, 추천에서 비추천 전환이 가능해야 한다.
- 추천 수, 비추천 수, 순추천 수를 저장하거나 집계 뷰로 제공한다.
- 작성자 본인 추천 허용 여부를 정책으로 정한다. 권장: 본인 추천은 허용하지 않는다.

### 개념글 정책

- 자동 등극 기준 예시: 작성 후 24시간 내 순추천 10 이상, 신고 임계치 미만, 삭제/숨김 아님.
- 게시판별 기준을 다르게 둘 수 있어야 한다.
- 운영자는 수동 등극/해제를 할 수 있다.
- 개념글 목록은 게시판별, 전체, 팔로우 게시판 기반 피드에서 볼 수 있어야 한다.
- 개념글 등극 시 작성자에게 알림을 보낸다.

## 6. 피드와 크로스포스트

현재 `/feed`와 피드 ↔ 게시판 공유가 구현되어 있다. 목표는 "게시판의 집단 흐름"과 "내가 구독한 흐름"을 함께 제공하는 것이다.

### 피드 요구

- 내가 팔로우한 유저의 피드 글을 보여준다.
- 내가 팔로우한 게시판의 개념글 또는 인기글을 섞어 보여준다.
- 내가 팔로우한 게시판의 모든 글을 볼지, 개념글만 볼지 사용자가 선택할 수 있게 한다.
- 피드 글은 제목 없이 짧은 포스트로 작성 가능하되, 게시판으로 공유할 때는 제목/말머리를 추가하게 한다.
- 크로스포스트는 원본 링크, 원본 작성자, 공유한 사람, 공유 시점이 구분되어야 한다.

### 크로스포스트 정책

- 게시판 글을 피드로 공유하면 원본을 참조하되, 삭제/숨김 상태가 동기화되어야 한다.
- 피드 글을 게시판으로 공유하면 게시판 문맥에 맞는 제목과 말머리를 요구한다.
- 동일 사용자가 같은 원본을 같은 게시판에 반복 공유하지 못하게 제한한다.
- 원본이 삭제되면 공유글은 "원본이 삭제됨" 상태를 표시한다.

## 7. 검색과 탐색

검색은 커뮤니티 사이트의 기본 기능이다. 초기부터 데이터 구조를 고려해야 한다.

### 검색 범위

- 전체 게시글 검색
- 게시판 내 검색
- 작성자 검색
- 댓글 검색
- 태그/말머리 검색
- 캐릭터/스티커/에셋 검색은 Phase 3 이후

### 검색 UX

- 검색 결과에는 게시판, 제목, 본문 일부, 작성자, 날짜, 댓글 수, 추천 수가 보여야 한다.
- 정렬은 정확도순, 최신순, 추천순을 제공한다.
- 검색어 하이라이트를 제공한다.
- 금칙어, 삭제글, 숨김글, 차단 사용자 콘텐츠는 검색 결과에서 제외한다.

## 8. 프로필과 신원

현재 `/profile`에는 닉네임, 아바타, 캐릭터 라이브러리, 구독 게시판 관리가 있다. 목표는 커뮤니티 작성자 정체성과 캐릭터 정체성을 함께 보여주는 것이다.

| 유형 | 정책 | 표시 |
|------|------|------|
| 고정닉 | 계정당 전역 유일 닉네임, 중복 불가 | 강조 뱃지 |
| 비고정닉 | 중복 허용 표시명, 계정 기반 | 중립 뱃지 |
| 비로그인 | 일회용 닉네임과 비밀번호로 작성 | IP 또는 대체 식별 표시 |

### 프로필 요구

- 닉네임, 아바타, 자기소개, 대표 캐릭터, 팔로워/팔로잉, 작성글, 댓글, 스크랩을 제공한다.
- 대표 캐릭터는 작성자 카드, 댓글, 리액션, 프로필 상단에 노출한다.
- 닉네임 변경 이력을 저장할지 정책을 정한다. 권장: 운영용으로 이력 저장, 공개 노출은 선택.
- 고정닉 예약/해제에는 쿨다운을 둔다.

## 9. 익명 글쓰기

익명 글쓰기는 커뮤니티 감각에 중요하지만 어뷰징 위험이 크다. 게시판별로 허용 여부를 설정한다.

- 비로그인 사용자는 게시판 정책이 허용할 때만 글/댓글을 작성할 수 있다.
- 작성 시 일회용 닉네임과 삭제/수정 비밀번호를 입력한다.
- 서버는 IP 해시, User-Agent 일부, 작성 시점 정보를 운영용으로 저장한다.
- 공개 화면에는 전체 IP가 아니라 부분 마스킹 또는 대체 식별자를 보여준다.
- 익명 작성자는 비밀번호로 본인 글/댓글 삭제를 할 수 있다.
- 신고/도배 방지를 위해 IP/브라우저 단위 레이트 리밋을 둔다.
