# 애니/만화/게임 작품 허브 설계

이 문서는 애니, 만화, 게임 작품 DB와 소개, 리뷰, 프리뷰, 평가, 뉴스, 작품별 커뮤니티 연결 작업을 할 때 참고한다. 커뮤니티 글/댓글은 [community.md](./community.md), DB 확장은 [data-model.md](./data-model.md), 화면 완료 기준은 [screen-acceptance.md](./screen-acceptance.md)를 함께 본다.

## 1. 제품 방향

10duck의 큰 축은 사용자가 "무엇을 볼지, 읽을지, 플레이할지" 결정하게 해주는 서브컬처 작품 허브다. 작품 정보 자체를 모으는 데서 끝나지 않고, 편집자의 프리뷰/리뷰, 유저 평가, 커뮤니티 반응, 뉴스 타임라인을 한 작품 페이지에 축적한다.

Live2D 캐릭터는 작품 탐색을 방해하지 않는 보조 연출로 둔다. 일반 사용자가 표정, 의상, 모션을 직접 제작해야 하는 흐름은 핵심 루프에서 제외한다.

## 2. 다루는 범위

- **애니:** TV, 극장판, OVA/ONA, 시즌별 신작, 후속 시즌, 스핀오프.
- **만화:** 출판 만화, 웹툰, 라이트노벨 원작, 단행본/연재 상태, 정발/전자책 여부.
- **게임:** 콘솔, PC, 모바일, 인디, 비주얼 노벨, 서브컬처 RPG, 출시 예정작, 라이브 서비스 업데이트.

게임은 애니/만화와 같은 `works` 모델을 공유하되 플랫폼, 개발사/퍼블리셔, 출시일, 가격/과금 형태, 플레이타임, 지원 언어, 스토어 링크처럼 게임 전용 필드를 가진다.

## 3. 핵심 사용자 흐름

1. 사용자가 홈이나 검색에서 작품을 발견한다.
2. 작품 상세에서 소개, 장르, 공식 링크, 출시/방영/연재 상태, 프리뷰, 리뷰, 유저 평가, 관련 게시글을 한 번에 확인한다.
3. 작품을 보고/읽고/플레이할지 결정한 뒤 관심 등록, 평가, 리뷰 작성, 커뮤니티 토론으로 이어진다.
4. 신작 시즌이나 출시 캘린더에서 앞으로 볼 작품을 고르고 알림을 설정한다.
5. 작품별 뉴스 타임라인을 통해 PV, 캐스팅, 발매일, 패치, 이벤트, 정발 소식 같은 업데이트를 따라간다.

## 4. 작품 페이지

작품 페이지는 커뮤니티 게시판보다 상위의 정보 허브로 동작한다.

### 공통 정보

- 대표 제목, 원제, 한국어 제목, 영문 제목, 별칭.
- 작품 유형: `ANIME`, `MANGA`, `GAME`.
- 대표 이미지, 배너, 공식 줄거리, 장르, 태그, 이용 등급, 국가/언어.
- 제작사/스튜디오/출판사/개발사/퍼블리셔.
- 원작, 후속작, 시즌, 스핀오프, 미디어믹스 관계.
- 공식 사이트, PV/트레일러, OTT, 전자책, 게임 스토어, 굿즈 링크.

### 애니 전용 정보

- 방영 분기, 방영 시작일/종료일, 총 화수, 방영 요일.
- 스튜디오, 감독, 각본, 음악, 주요 성우.
- 국내 시청 가능 OTT와 공개 시간.

### 만화 전용 정보

- 연재 시작일/종료일, 연재 상태, 출판사, 잡지/플랫폼.
- 권수/화수, 정발 여부, 전자책/종이책 링크.
- 원작/작화 분리 표기.

### 게임 전용 정보

- 출시일, 플랫폼, 개발사, 퍼블리셔, 장르, 플레이 방식.
- 가격, 과금 형태: 패키지, 부분유료, 구독, DLC, 가챠 여부.
- 한국어 지원, 멀티플레이 여부, 예상 플레이타임.
- 스팀/닌텐도/플레이스테이션/엑스박스/모바일 스토어 링크.
- 주요 업데이트, 시즌, 이벤트, 패치 노트 타임라인.

## 5. 프리뷰와 리뷰

프리뷰는 출시/방영/정발 전후의 선택 가이드다. 리뷰는 감상/플레이 후 판단 근거를 제공한다.

### 프리뷰 항목

- 기대 포인트.
- 우려 포인트.
- 입문 난이도.
- 원작 팬에게 중요한 변경 가능성.
- 비슷한 작품 추천.
- "누구에게 추천/비추천" 판정.
- 애니는 1화/3화 체크, 만화는 초반 권/화 체크, 게임은 데모/초반 플레이 체크를 기준으로 둔다.

### 리뷰 항목

- 스포일러 없음 요약과 스포일러 포함 본문을 분리한다.
- 애니/만화/게임 공통 평가는 스토리, 캐릭터, 연출, 몰입도, 완성도, 추천도를 둔다.
- 애니는 작화, 음악/성우, 원작 충실도 항목을 추가한다.
- 만화는 작화, 컷 구성, 전개 속도, 번역/정발 품질 항목을 추가한다.
- 게임은 조작감, 시스템, 밸런스, 최적화, 과금 압박, 반복 플레이 가치 항목을 추가한다.

## 6. 유저 평가

단순 별점만으로는 차별성이 약하다. 10duck은 덕후식 판단 태그와 정량 점수를 함께 사용한다.

- 별점 또는 100점 점수.
- 한 줄 판정: `찍먹 추천`, `3화까지 봐야 함`, `원작 팬 전용`, `정주행용`, `스포 주의`, `패치 후 재평가`, `세일 때 추천`.
- 장르/취향 태그: `작화맛집`, `캐릭터맛집`, `서사중심`, `피폐`, `힐링`, `전투`, `추리`, `수집형`, `스토리겜`, `라이브서비스`.
- 스포일러 포함 여부를 평가/리뷰 단위로 저장한다.
- 작품의 종합 평점은 전체 평균만 보여주지 말고, 취향 태그 분포와 추천/비추천 이유를 함께 보여준다.

## 7. 뉴스와 업데이트 타임라인

초기에는 언론사처럼 매일 기사를 쓰기보다 작품별 업데이트 로그를 쌓는다.

- PV/트레일러 공개.
- 방영일, 출시일, 정발일, 플랫폼 확정.
- 캐스팅, 제작진, 개발사/퍼블리셔 발표.
- 게임 패치, 시즌 이벤트, DLC, 콜라보, 서비스 종료.
- 만화 휴재, 완결, 단행본 발매, 애니화 발표.
- 뉴스 항목마다 출처 URL과 작성/확인 시각을 저장한다.
- 루머와 공식 발표는 명확히 구분한다.

## 8. 외부 데이터 소스와 캐싱 정책

페이즈 3의 작품 허브는 처음부터 모든 작품 정보를 직접 입력하는 방식으로 시작하지 않는다. 외부 작품 메타데이터를 검색/동기화하고, 10duck 내부에서는 한국어 소개, 프리뷰, 리뷰, 평가, 커뮤니티 반응, 운영진 큐레이션을 쌓아 차별화한다.

### 권장 소스

| 영역 | 우선 소스 | 용도 | 주의점 |
|------|-----------|------|--------|
| 애니/만화 메타데이터 | [AniList GraphQL API](https://github.com/AniList/docs) | 제목, 원제, 별칭, 장르, 태그, 방영/연재 상태, 커버, 관계 작품, 캐릭터/스태프 | 한국어 설명과 국내 서비스 정보는 약하므로 자체 보강 필요 |
| 애니/만화 보조 매핑 | [Kitsu API](https://hummingbird-me.github.io/api-docs/) | 외부 ID 보조, 검색 보정, 평점/상태 보조 | 메인 소스가 아니라 보조 매핑용으로 사용 |
| MyAnimeList 기반 보조 | [Jikan API](https://docs.jikan.moe/) | MAL ID 조회, 검색 보조, 외부 링크 연결 | 비공식 API라 핵심 DB 의존도를 낮게 둔다 |
| 게임 메타데이터 | [IGDB API](https://api-docs.igdb.com/) | 게임명, 플랫폼, 출시일, 장르, 회사, 커버, 스크린샷, 연령등급 | Twitch 앱 등록 필요. 상업 활용 조건은 별도 확인 필요 |
| 게임 MVP 대안 | [RAWG API](https://rawg.io/apidocs) | 빠른 게임 검색/출시 캘린더 MVP | 무료/상업 조건, 요청 제한, attribution 조건 확인 필요 |
| 만화책/라노벨/ISBN | [Rakuten Books API](https://webservice.rakuten.co.jp/documentation/books-book-search) | ISBN, 저자, 출판사, 출간일, 표지, 구매 링크 | 일본 출판물 중심. 국내 정발 정보는 별도 보강 필요 |

### 뉴스와 출처

뉴스는 외부 기사 본문을 저장하지 않는다. 초기에는 공식 사이트, 공식 X/YouTube, 퍼블리셔 공지, OTT/스토어 공지, 신뢰 가능한 매체의 URL을 작품 타임라인에 연결한다.

저장해도 되는 정보:

- 제목
- 출처명
- 원문 URL
- 발행일/확인일
- 공식/루머/매체 보도 구분
- 운영진이 직접 작성한 짧은 요약과 코멘트

저장하지 않는 정보:

- 외부 기사 본문 전체
- 외부 리뷰 전문
- 라이선스가 불명확한 이미지 원본 복제
- 유료 기사나 제한 콘텐츠의 본문

### DB 저장 원칙

외부 데이터를 통째로 복제하지 말고, 작품 식별과 화면 표시를 위한 최소 필드만 캐싱한다.

권장 필드:

- `external_source`: `anilist`, `kitsu`, `jikan`, `igdb`, `rawg`, `rakuten_books`
- `external_id`: 각 소스의 고유 ID
- `external_url`
- `last_synced_at`
- `sync_status`: `PENDING`, `SYNCED`, `FAILED`, `MANUAL_REVIEW`
- `license_note`: 상업 사용/표시 의무/주의점 메모

캐싱해도 되는 대표 필드:

- 제목, 원제, 영어 제목, 별칭
- 작품 타입, 상태, 시작일/출시일, 시즌
- 장르/태그
- 제작사/출판사/개발사/퍼블리셔
- 공식 사이트 URL, 스토어 URL
- 외부 이미지 URL 또는 사용 허용이 확인된 썸네일

10duck이 직접 만들어야 하는 필드:

- 한국어 소개문
- 프리뷰/리뷰 본문
- 추천/비추천 이유
- 스포일러 안내
- 국내 OTT/전자책/스토어 접근성
- 운영진 큐레이션 태그
- 유저 평가, 댓글, 커뮤니티 반응

### 초기 구현 순서

1. `works`, `work_external_ids`, `work_titles`를 먼저 설계한다.
2. AniList 검색 연동으로 애니/만화 작품 생성 MVP를 만든다.
3. IGDB 또는 RAWG 중 하나로 게임 검색 연동을 붙인다.
4. 외부 ID가 있는 작품만 동기화하고, 수동 생성 작품도 허용한다.
5. 뉴스는 RSS 크롤러보다 운영진 수동 등록 + URL 저장으로 시작한다.
6. 상업화 전에는 각 API의 attribution, 요청 제한, 상업 사용 조건을 다시 점검한다.

### 판단

페이즈 3에서 가장 먼저 필요한 것은 완벽한 데이터 수집기가 아니라, 외부 ID를 붙일 수 있는 내부 작품 DB 구조다. 외부 API는 작품 생성과 보강을 돕는 도구로 두고, 서비스의 핵심 가치는 10duck 내부 리뷰, 평가, 프리뷰, 커뮤니티 반응에 쌓는다.

## 9. 탐색 화면

### 시즌 애니 프리뷰

- 분기별 신작 리스트.
- 장르, 원작 여부, 스튜디오, OTT, 기대도, 1화 반응, 추천 태그 필터.
- "이번 분기 입문 추천", "작화 기대작", "원작 팬 체크", "가볍게 볼 작품" 같은 편집 섹션.

### 신작 만화/정발 캘린더

- 신규 연재, 단행본 발매, 정발 예정, 전자책 공개.
- 장르와 출판/플랫폼 필터.
- 무료 회차/체험 링크가 있으면 표시한다.

### 게임 출시 캘린더

- 플랫폼별 출시 예정작.
- 체험판/데모 제공 여부.
- 가격, 한국어 지원, 멀티플레이, 가챠/과금 형태 필터.
- 출시 후 유저 평가와 리뷰를 빠르게 연결한다.

## 10. 커뮤니티 연결

- `posts`는 선택적으로 `work_id`를 가진다.
- 작품 페이지에는 관련 게시글, 리뷰글, 질문글, 스포일러 토론을 모아 보여준다.
- 작품별 기본 탭은 `정보`, `리뷰`, `프리뷰`, `뉴스`, `커뮤니티`, `평가`로 둔다.
- 스포일러 게시글은 작품 페이지에서 접힌 상태로 표시한다.
- 게시판은 계속 존재하되, 작품 중심 글은 작품 허브에도 동시에 노출될 수 있다.

## 11. 수익화

- 검색 유입이 많은 작품 소개/프리뷰/리뷰 페이지에 광고를 붙인다.
- OTT, 전자책, 만화책, 게임 스토어, 굿즈 제휴 링크를 작품 페이지에 연결한다.
- 스폰서드 프리뷰와 일반 리뷰는 명확히 구분한다.
- 프리미엄 기능은 광고 제거, 취향 기반 추천, 방영/출시/정발 알림, 내 평가 통계, 스포일러 고급 필터로 시작한다.
- 게임은 할인/출시 알림, DLC/시즌 업데이트 알림, 플랫폼별 가격 비교로 확장할 수 있다.

## 12. MVP 완료 기준

- 애니/만화/게임을 하나의 작품 DB에서 구분해 저장할 수 있다.
- 작품 상세에서 공통 정보와 유형별 핵심 정보가 깨지지 않게 표시된다.
- 작품에 리뷰, 평가, 뉴스 타임라인, 커뮤니티 글을 연결할 수 있다.
- 시즌 애니, 신작 만화, 게임 출시 예정작 중 최소 하나의 탐색 화면이 실제 데이터로 동작한다.
- 스포일러 없는 영역과 스포일러 포함 영역이 분리된다.
- 작품 페이지에서 외부 공식 링크와 제휴 링크를 구분해 표시할 수 있다.
