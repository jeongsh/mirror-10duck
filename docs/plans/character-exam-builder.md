# 캐릭터 중간고사 빌더 기획서

이 문서는 작품/캐릭터 DB를 바이럴 콘텐츠와 추천 데이터로 활용하기 위한 **운영자용 캐릭터 시험 빌더** 기획이다. 핵심 컨셉은 "한국 학교 중간고사" 형식의 캐릭터 이해도 시험이며, 유저에게는 놀이형 시험 콘텐츠로 보이고 서비스에는 캐릭터 태그, 팬덤 인식, 취향, 추천 신호가 쌓이게 한다.

## 1. 목표

### 사용자 목표

- 좋아하는 캐릭터를 얼마나 잘 아는지 시험처럼 풀어본다.
- 점수, 등급, 백분위, 생활기록부 코멘트가 포함된 결과지를 받는다.
- 결과 이미지를 공유하고 다른 캐릭터 시험으로 이어간다.
- 내가 고른 답을 바탕으로 취향이 비슷한 캐릭터/작품을 추천받는다.

### 운영 목표

- 2천 개 이상 캐릭터를 개별 문항 수작업 없이 시험 콘텐츠로 활용한다.
- 유저 응답을 통해 캐릭터별 태그 후보와 팬덤 인식 데이터를 모은다.
- 바이럴팀이 직접 시험, 문항 템플릿, 결과 문구, 추천 섹션을 운영한다.
- 신규 캐릭터가 추가되어도 데이터 수준에 맞는 시험을 자동 생성한다.
- 공식 태그와 팬덤 인식 태그를 분리해 추천과 콘텐츠 제작에 재사용한다.

## 2. 제품 컨셉

서비스명 후보:

- `캐릭터 탐구 중간고사`
- `2026학년도 최애 이해력 평가`
- `덕력평가 모의고사`
- `작품명 영역 - 캐릭터 탐구`
- `최애 생활기록부`

사용자-facing 톤:

- 시험지, OMR, 수험번호, 제한 시간, 등급, 석차, 오답노트, 생활기록부를 적극 사용한다.
- 너무 진지한 교육 서비스가 아니라 "학교 시험 패러디"로 간다.
- 의견형 문항은 틀렸다고 표현하지 않고 "해석 차이"로 표현한다.

예시 결과:

```text
2026학년도 캐릭터 탐구 중간고사

점수: 86점
등급: 2등급
백분위: 상위 11%

평가:
공식 설정 이해도는 높지만, 이 캐릭터를 평균보다 더 다정한 인물로 해석하고 있습니다.

생활기록부:
겉으로는 무심하나 관계에 대한 책임감이 강하며,
위기 상황에서 혼자 떠안는 경향이 있음.
```

## 3. 핵심 원칙

1. **캐릭터별 문항을 만들지 않는다.**
   - 운영자는 캐릭터마다 문제를 직접 쓰지 않는다.
   - 공통 문항 템플릿과 캐릭터 데이터를 조합해 시험을 생성한다.

2. **빌더는 운영자 도구로 완성한다.**
   - 문항 템플릿, 출제 조건, 선택지 태그, 결과 문구, 추천 규칙까지 관리한다.
   - 개발자가 매번 하드코딩하지 않아도 운영자가 시험을 추가/수정할 수 있어야 한다.

3. **정답형과 해석형을 분리한다.**
   - 공식 설정 문제는 점수에 반영한다.
   - 성향/매력/관계성 문제는 태그 신호와 취향 프로필에 반영한다.
   - 해석형 문제를 오답으로 취급하지 않는다.

4. **태그는 자유 입력이 아니라 사전 기반으로 관리한다.**
   - 선택지는 여러 태그 신호를 남길 수 있다.
   - 신규 태그 제안은 가능하지만 승인 전에는 공식 태그로 쓰지 않는다.

5. **신규 캐릭터는 시험을 통해 데이터가 완성되게 한다.**
   - 데이터가 부족한 캐릭터도 의견형/취향형 시험은 가능해야 한다.
   - 응답이 쌓이면 태그 후보와 더 정교한 문항을 만들 수 있다.

## 4. 사용자 흐름

### 4.1 캐릭터 단일 시험

1. 사용자가 캐릭터 상세 또는 바이럴 허브에서 `중간고사 보기`를 누른다.
2. 시험 표지 화면에서 캐릭터명, 작품명, 문항 수, 예상 소요 시간, 스포일러 포함 여부를 확인한다.
3. 사용자가 시험을 시작한다.
4. 10~15문항을 푼다.
5. 결과지에서 점수, 등급, 해석 유형, 생활기록부, 추천 캐릭터를 확인한다.
6. 결과 이미지를 저장하거나 공유한다.
7. 비슷한 캐릭터 시험 또는 같은 작품 시험으로 이어진다.

### 4.2 작품 단위 시험

1. 사용자가 작품 상세에서 `작품 캐릭터 중간고사`를 누른다.
2. 작품 내 캐릭터 여러 명이 섞인 시험을 푼다.
3. 결과에서 "이 작품에서 내가 제일 잘 아는 캐릭터", "내 해석이 가장 팬덤 평균과 가까운 캐릭터"를 보여준다.

### 4.3 추천형 시험

1. 사용자가 바이럴 허브에서 `내 취향 캐릭터 반 배치고사`를 시작한다.
2. 여러 캐릭터 상황/매력 선택지를 고른다.
3. 결과에서 취향 태그와 추천 캐릭터를 보여준다.

## 5. 문항 유형

### 5.1 공식 설정형

목적:

- 시험의 신뢰감을 만든다.
- 캐릭터/작품 인지도와 숙련도를 측정한다.

예시:

- 다음 중 `{character_name}`의 공식 설정에 가장 가까운 것은?
- `{character_name}`이 속한 작품은?
- `{character_name}`과 가장 관계가 깊은 인물은?

데이터 활용:

- 정답 점수
- 공식 설정 이해도
- 작품/캐릭터 인지도

조건:

- 캐릭터에 공식 설정 요약, 작품 연결, 관계 캐릭터가 있어야 고품질 문항 생성 가능
- 스포일러 레벨 필수

### 5.2 상황 반응 추론형

목적:

- 유저가 캐릭터 성격을 어떻게 해석하는지 수집한다.

예시:

- `{character_name}`이 친구가 위험에 처한 상황에서 가장 먼저 할 행동은?
- `{character_name}`이 고백을 받았을 때 가장 가까운 반응은?

선택지 예:

| 선택지 | 태그 신호 |
|--------|-----------|
| 아무렇지 않은 척하지만 뒤에서 계속 신경 쓴다 | 무심다정, 감정표현서툼, 은근보호 |
| 바로 감정을 확인하고 정면으로 부딪힌다 | 직진형, 솔직함, 관계중심 |
| 농담처럼 넘기지만 속으로는 흔들린다 | 능글형, 회피형, 내면갈등 |
| 거리를 두며 혼자 정리하려 한다 | 방어적, 고립형, 상처보유 |

데이터 활용:

- 캐릭터 성격 태그 후보
- 유저 취향 태그
- 팬덤 평균 해석

### 5.3 대사 선택형

목적:

- 캐릭터 말투와 바이럴 카피 소재를 수집한다.

예시:

- 다음 중 `{character_name}`이 가장 할 법한 말은?
- 위기 상황에서 `{character_name}`의 한마디로 가장 적절한 것은?

데이터 활용:

- 말투 태그
- 캐릭터 보이스
- 바이럴 문구 생성 보조

조건:

- 대표 대사나 말투 태그가 있으면 우선 출제
- 데이터가 부족하면 일반 선택지 기반으로 출제

### 5.4 매력 포인트형

목적:

- 팬덤이 캐릭터에 반응하는 이유를 수집한다.

예시:

- `{character_name}`의 가장 강한 매력은?
- 이 캐릭터가 인기 있는 이유에 가장 가까운 것은?

데이터 활용:

- 매력 포인트 태그
- 바이럴 소재 후보
- 결과지 코멘트

### 5.5 관계성/케미형

목적:

- 캐릭터 간 추천 그래프와 관계성 태그를 만든다.

예시:

- `{character_name}`과 가장 잘 어울리는 상대 유형은?
- `{character_name}`과 붙었을 때 가장 재미있는 관계성은?

데이터 활용:

- 관계성 태그
- 캐릭터 유사도/보완도
- 같은 작품/타 작품 추천

조건:

- 관계 캐릭터가 있으면 구체 문항
- 없으면 상대 유형 선택형으로 대체

### 5.6 학교생활 밈형

목적:

- 공유성과 결과 이미지 재미를 만든다.

예시:

- 담임 선생님이 `{character_name}` 생활기록부에 적을 말은?
- `{character_name}`의 교무실 호출 사유는?
- `{character_name}`이 수행평가에서 받을 평가는?

데이터 활용:

- 팬덤 밈 태그
- 결과지 생활기록부 문구
- 공유 이미지 소재

## 6. 시험 구성

기본 캐릭터 시험은 10~15문항으로 구성한다.

추천 비율:

| 유형 | 기본 문항 수 | 점수 반영 |
|------|--------------|-----------|
| 공식 설정형 | 2~3 | O |
| 상황 반응 추론형 | 3 | 해석 점수 |
| 대사 선택형 | 1~2 | 해석 점수 |
| 매력 포인트형 | 2 | 태그 신호 |
| 관계성/케미형 | 1~2 | 태그 신호 |
| 학교생활 밈형 | 1 | 태그 신호/공유성 |

점수 체계:

- `공식 점수`: 정답이 있는 문항의 점수
- `해석 일치도`: 운영자 태그 또는 팬덤 평균과 얼마나 가까운지
- `취향 프로필`: 유저가 반복 선택한 태그 조합
- `팬덤 평균 차이`: 다수 응답과 다른 해석 포인트

등급 예:

| 점수/일치도 | 등급 | 표현 |
|-------------|------|------|
| 상위 4% | 1등급 | 공식 팬 인증 |
| 상위 11% | 2등급 | 시험지에 낙서해도 맞히는 타입 |
| 상위 23% | 3등급 | 감정선은 강하지만 설정 복습 필요 |
| 상위 40% | 4등급 | 좋아하지만 헷갈리는 부분 있음 |
| 그 외 | 보충학습 | 작품 복습 권장 |

## 7. 운영자 빌더 범위

빌더는 `/admin` 하위 운영자 도구로 제공한다.

### 7.1 시험 상품 빌더

시험 콘텐츠 단위를 만든다.

관리 항목:

- 시험명
- 시험 설명
- 시험 유형: 캐릭터 단일 / 작품 단위 / 장르 단위 / 추천형
- 기본 문항 수
- 제한 시간
- 공개 상태: 초안 / 검수 요청 / 승인 / 예약 공개 / 공개 / 중지
- 대상 캐릭터 조건
- 스포일러 허용 레벨
- 결과지 템플릿
- 공유 이미지 템플릿
- 추천 섹션 사용 여부

필수 기능:

- 시험 복제
- 예약 공개
- 미리보기
- 공개 전 검수 체크리스트
- 비공개/중지

### 7.2 문항 템플릿 빌더

재사용 가능한 문항 틀을 관리한다.

관리 항목:

- 문항 유형
- 질문 문장
- 사용 가능한 변수: `{character_name}`, `{work_title}`, `{related_character_name}`, `{genre}`
- 선택지 2~5개
- 선택지별 태그 매핑
- 정답 여부
- 점수 배점
- 해석형 여부
- 스포일러 레벨
- 출제 조건
- 사용 가중치
- 비활성화 여부

템플릿 예:

```text
질문:
{character_name}이(가) 고백을 받았을 때 가장 가까운 반응은?

선택지:
A. 아무렇지 않은 척하지만 뒤에서 계속 신경 쓴다
B. 바로 감정을 확인하고 정면으로 부딪힌다
C. 농담처럼 넘기지만 속으로는 흔들린다
D. 거리를 두며 혼자 정리하려 한다
```

### 7.3 출제 규칙 빌더

캐릭터 데이터에 따라 어떤 템플릿을 쓸지 결정한다.

조건 예:

- 장르가 `로맨스`인 캐릭터에게만 사용
- 성격 태그가 1개 이상 있는 캐릭터에게만 사용
- 관계 캐릭터가 있는 경우만 사용
- 대표 대사가 있는 캐릭터에게만 대사형 문항 사용
- 스포일러 레벨 2 이하만 공개 시험에 사용
- 신규 캐릭터는 매력/상황/밈형 비중을 높임

규칙 필드:

- 대상 캐릭터 필터
- 제외 조건
- 문항 유형 비율
- 템플릿 우선순위
- 랜덤성 정도
- 같은 태그 반복 제한
- 최근 출제 문항 제외 기간

### 7.4 결과지 빌더

점수와 태그 조합에 따라 결과 문구를 만든다.

관리 항목:

- 점수 구간별 제목
- 등급/백분위 표현
- 공식 점수 코멘트
- 해석 일치도 코멘트
- 태그 조합별 생활기록부 문장
- 강점/약점 과목명
- 오답노트 문구
- 공유 이미지용 한 줄 문구

조건 예:

```text
조건:
선택 태그에 "무심다정" + "책임감"이 많음

결과 문구:
당신은 이 캐릭터를 겉은 차갑지만 관계에는 끝까지 책임지는 인물로 해석하고 있습니다.
```

### 7.5 추천 규칙 빌더

시험 종료 후 노출할 추천을 관리한다.

추천 타입:

- 유사 태그 캐릭터
- 같은 작품 내 다른 캐릭터
- 같은 장르 작품
- 팬덤 평균 해석이 비슷한 유저들이 좋아한 캐릭터
- 공식 설정 오답과 관련된 작품/캐릭터

관리 항목:

- 추천 섹션 제목
- 추천 후보 필터
- 태그 가중치
- 제외 조건
- 공개 가능 캐릭터만 노출
- 추천 사유 문구 템플릿

### 7.6 검수/시뮬레이터

운영자가 실제 유저 화면을 확인한다.

필수 기능:

- 캐릭터 선택 후 시험 생성 미리보기
- 문항별 템플릿 출처 표시
- 선택지별 태그 신호 표시
- 스포일러 문항 표시
- 결과지 시뮬레이션
- 추천 결과 시뮬레이션
- 데이터 부족 경고
- 공개 전 체크리스트

## 8. AI 보조 기능

AI는 빌더 안에서 초안을 만드는 보조 기능으로만 사용한다. AI 생성물은 바로 공개하지 않는다.

지원 기능:

- 캐릭터 소개 기반 문항 후보 생성
- 공식 설정 요약에서 정답형 문제 생성
- 선택지 후보 생성
- 선택지별 태그 추천
- 생활기록부 문구 생성
- 결과지 문구 생성
- 추천 사유 문구 생성

상태 흐름:

```text
AI 초안 -> 운영자 수정 -> 검수 요청 -> 승인 -> 사용
```

주의:

- 스포일러 레벨이 불명확한 AI 문항은 공개 불가
- 공식 설정형 문항은 사람이 정답 검수해야 함
- 태그 매핑은 태그 사전에서만 선택

## 9. 캐릭터 데이터 수준

2천 개 이상의 캐릭터를 한 번에 완성할 수 없으므로, 캐릭터별 시험 가능 수준을 둔다.

| 레벨 | 보유 데이터 | 가능한 시험 |
|------|-------------|-------------|
| Level 0 | 이름, 작품명 | 일반 취향형/밈형 |
| Level 1 | 기본 태그 3개 이상 | 상황/매력/관계성 문항 |
| Level 2 | 공식 설정 요약 | 공식 설정형 포함 |
| Level 3 | 대표 대사, 관계 캐릭터, 이미지 | 고품질 캐릭터 시험 |

캐릭터 관리 화면에 표시할 상태:

- 시험 생성 가능 여부
- 부족한 필드
- 추천 가능 여부
- 공개 가능 여부
- 스포일러 데이터 포함 여부
- 유저 응답 수
- 태그 후보 수

## 10. 태그 체계

태그는 `공식 태그`와 `팬덤 인식 태그`를 분리한다.

### 10.1 태그 카테고리

- 성격
- 말투
- 관계성
- 매력 포인트
- 장르 감성
- 팬덤 밈
- 바이럴 소재
- 추천용 속성
- 스포일러/주의

### 10.2 태그 신뢰도 단계

```text
raw_signal -> aggregated_signal -> candidate_tag -> approved_tag
```

설명:

- `raw_signal`: 유저 개별 응답
- `aggregated_signal`: 캐릭터별 태그 집계
- `candidate_tag`: 운영자에게 제안된 태그 후보
- `approved_tag`: 운영자가 승인한 공식/팬덤 태그

승인 기준 예:

- 응답 수 50건 이상
- 특정 태그 선택률 40% 이상
- 최근 30일 유지
- 상반 태그와 충돌 낮음
- 운영자 승인

## 11. 관리자 권한

권한 역할:

| 역할 | 가능 액션 |
|------|-----------|
| 바이럴 운영자 | 시험/문항/결과 문구 초안 작성, 미리보기 |
| 콘텐츠 운영자 | 캐릭터 태그, 공식 설정, 스포일러 검수 |
| 관리자 | 공개 승인, 추천 규칙 설정, 중지/삭제 |
| 개발자 | 태그 사전, 시스템 규칙, 권한 설정 |

콘텐츠 상태:

```text
초안 -> 검수 요청 -> 수정 필요 / 승인 -> 예약 공개 -> 공개 -> 중지
```

감사 로그:

- 생성자
- 수정자
- 승인자
- 공개/중지 시각
- 변경 전후 diff
- AI 생성 여부

## 12. 데이터 모델 초안

정확한 컬럼은 구현 시 현재 Supabase 스키마를 기준으로 조정한다.

### 12.1 시험/빌더

- `character_exam_products`
  - 시험 상품 단위
  - type, title, status, question_count, time_limit_seconds, spoiler_level, result_template_id

- `character_exam_templates`
  - 문항 템플릿
  - question_type, body, variables, scoring_type, spoiler_level, weight, status

- `character_exam_template_options`
  - 템플릿 선택지
  - template_id, label, body, is_correct, score, tag_payload

- `character_exam_rules`
  - 출제 규칙
  - product_id, condition_json, question_mix_json, priority, enabled

- `character_exam_result_templates`
  - 결과지 문구/등급/생활기록부 템플릿

- `character_exam_recommendation_rules`
  - 시험 종료 후 추천 규칙

### 12.2 실행/응답

- `character_exam_sessions`
  - 유저가 실제로 푼 시험 1회
  - user_id nullable, product_id, character_id nullable, work_id nullable, started_at, completed_at

- `character_exam_questions`
  - 세션에 생성된 실제 문항 스냅샷
  - session_id, template_id, character_id, question_body, options_snapshot

- `character_exam_responses`
  - 유저 응답
  - session_id, question_id, option_id, response_time_ms, score_delta, tag_payload

- `character_tag_signals`
  - 응답에서 파생된 캐릭터 태그 신호
  - character_id, tag_id, source, weight, session_id, response_id

- `user_preference_signals`
  - 유저 취향 신호
  - user_id nullable, tag_id, weight, source

- `character_similarity_signals`
  - 캐릭터 간 유사/보완 신호

### 12.3 운영/검수

- `character_tag_candidates`
  - 유저 응답 기반 태그 후보
  - character_id, tag_id, signal_count, signal_ratio, status

- `exam_builder_audit_logs`
  - 빌더 변경 이력

### Phase 1. 기반 빌더

- 시험 상품 CRUD
- 문항 템플릿 CRUD
- 선택지별 태그 매핑
- 출제 조건

완료 기준:

### Phase 2. 결과지/추천/공유

- 결과지 빌더
- 공유 이미지 생성
- 추천 규칙 빌더
- 캐릭터/작품 상세 진입 연결
- 팬덤 평균 비교
- 기본 운영 지표 대시보드

완료 기준:

- 결과 공유와 다음 시험 전환이 가능하다.
- 시험 결과가 추천으로 이어진다.

### Phase 3. 태그 후보 검수

- 태그 후보 집계
- 공식 태그/팬덤 인식 태그 분리
- 승인/반려/보류 플로우
- 캐릭터 데이터 수준 표시
- 데이터 부족 캐릭터 큐

완료 기준:

- 유저 응답이 운영자가 검수 가능한 태그 후보로 올라온다.

### Phase 4. AI 보조

- AI 문항 초안 생성
- AI 결과 문구 초안 생성
- AI 선택지 태그 추천
- 검수 상태 연동

완료 기준:

- 신규 캐릭터/신규 시험의 운영 제작 시간이 줄어든다.

## 17. 리스크와 대응

### 스포일러

- 문항/템플릿/결과 문구에 스포일러 레벨을 둔다.
- 시험 시작 전 스포일러 포함 여부를 표시한다.
- 공유 이미지에는 스포일러 문항 결과를 노출하지 않는다.

### 공식 설정과 팬 해석 충돌

- 공식 설정형과 해석형을 UI에서 분리한다.
- 의견형 문항은 오답으로 처리하지 않는다.
- 결과 문구는 "팬덤 평균과 다름"으로 표현한다.

### 태그 오염

- 태그 자유 입력을 제한한다.
- 태그 후보는 승인 전까지 추천 공식 신호로 쓰지 않는다.
- 응답 수가 적은 태그는 후보로만 유지한다.

### 운영 복잡도

- 빌더 화면을 시험 상품, 문항 템플릿, 결과지, 추천, 시뮬레이터로 분리한다.
- 운영자 권한과 승인 플로우를 둔다.
- 공개 전 시뮬레이터를 필수로 사용하게 한다.

## 19. 채택 기준

초기 공개 후 4주 기준:

- 시험 완료율 60% 이상
- 결과 공유 클릭률 10% 이상
- 시험 후 다른 시험 전환율 15% 이상
- 캐릭터별 태그 신호 1만 건 이상
- 운영자가 승인한 신규 태그 후보 100개 이상
- 시험 후 작품/캐릭터 상세 진입률 8% 이상

채택 실패 시:

- 시험 UI/결과 공유는 유지하되 태그 수집/추천 연동 범위를 축소한다.
- 운영자 빌더는 문항 템플릿/결과지 관리 도구로 계속 활용한다.
