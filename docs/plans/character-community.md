# 캐릭터와 커뮤니티 연결 설계

이 문서는 Live2D, 캐릭터 리액션, 스티커 팩, 대표 캐릭터, 목적형 덕질 비서, 후순위 AI 롤플레잉 채팅 작업을 할 때 참고한다. Live2D 구현 구조는 [../LIVE2D_CHARACTER_GUIDE.md](../LIVE2D_CHARACTER_GUIDE.md)와 [../ARCHITECTURE_OVERVIEW.md](../ARCHITECTURE_OVERVIEW.md)를 함께 본다.

## 1. 현재 구현

- 전역 Live2D 캐릭터 렌더링
- 캐릭터 라이브러리와 업로드
- 스티커 토큰 삽입 및 `RichContent` 렌더링
- 게시글 감정 리액션 6종
- 댓글의 스티커-only 답글
- 리액션 시점의 캐릭터 썸네일 스냅샷
- 알림 수신 시 Live2D 말풍선과 감정 상태 변경
- 모델 히트 영역 기반 터치 액션(`tap_head`, `tap_body`, `tap_other`)과 액션별 모션/대사/사운드 재생

## 2. 목표 경험

- 내 대표 캐릭터가 커뮤니티 활동의 시각적 서명처럼 동작한다.
- 글을 쓰거나 댓글을 받을 때 캐릭터가 상황에 맞게 반응한다.
- 감정 리액션은 단순 좋아요가 아니라 캐릭터 표정과 연결된다.
- 프로필 페이지에서는 사람 계정과 캐릭터 정체성이 함께 보인다.
- 스티커는 커뮤니티 밈과 캐릭터 애착을 만드는 핵심 에셋이 된다.
- 캐릭터는 자유 대화 상대보다 커뮤니티 활동과 알림을 돕는 덕질 비서에 가깝게 동작한다.
- 롤플레잉 채팅은 후순위 확장으로 남기되, 초기 핵심 경험과 안전 정책을 침범하지 않는다.

## 3. 대표 캐릭터와 작성자 표시

- 사용자는 프로필에서 대표 캐릭터를 선택할 수 있어야 한다.
- 게시글/댓글/리액션에는 작성 시점 대표 캐릭터 스냅샷을 저장할지 결정한다.
- 캐릭터가 삭제되어도 과거 리액션/스티커가 깨지지 않게 썸네일 또는 에셋 스냅샷을 보존한다.
- 작성자 카드에는 닉네임, 신원 뱃지, 아바타, 대표 캐릭터 진입을 함께 제공한다.

## 4. 스티커 제품 방향

- 캐릭터를 만든 직후에는 스티커가 자동으로 생기지 않는다.
- 스티커는 캐릭터의 Live2D 표정/모션 지원 여부와 분리된 별도 에셋이다.
- 사용자가 직접 이미지 파일을 등록하거나, 명시적으로 "AI로 스티커 만들기"를 실행했을 때만 스티커 에셋이 생성되고 커뮤니티에 연결된다.
- AI 연동 시에도 "스티커 만들기" 플로우 안에서만 캐릭터를 참조해 디시콘 스타일 스티커를 생성한다. AI가 캐릭터 등록 직후 임의로 전체 감정 세트를 만들지 않는다.
- 스티커 세트에는 `기본/기쁨/슬픔/놀람/응원` 같은 추천 라벨을 제공하되 필수 개수로 강제하지 않는다. `윙크/두근/부끄` 같은 저빈도 표현은 선택 라벨로 둔다.
- 스티커 관리 페이지에서 보유 스티커, 감정 세트, 삭제, 다시 만들기, 공개/비공개 설정을 제공한다.

### 캐릭터 감정과 스티커 라벨 분리

Live2D 캐릭터 감정은 런타임 연출 능력이고, 스티커 라벨은 사용자가 등록한 이미지 에셋의 분류다. 따라서 어떤 캐릭터가 `wink` 표정을 지원하지 않아도 사용자가 직접 만든 윙크 이미지 스티커를 등록할 수 있다. 반대로 캐릭터가 `wink` 표정을 지원하더라도 스티커 에셋이 없으면 커뮤니티 스티커 피커에는 나타나지 않는다.

- 캐릭터 등록 최소 요건은 모델 로딩 가능, 썸네일, 기본 위치다.
- 커뮤니티 스티커 노출 기준은 `sticker_assets` 존재 여부다.
- 기존 `:sticker/{characterId}/{emotion}:` 토큰은 레거시 렌더링으로 유지하지만, 신규 에디터는 스티커 에셋 ID 기반 저장으로 전환한다.

## 5. 캐릭터 안전 정책

업로드 캐릭터는 외형, 나이, 원작 맥락을 서비스가 완전히 알 수 없다. 따라서 기본 상호작용은 모든 캐릭터가 미성년자처럼 보일 가능성을 고려해 전체 이용가 수준으로 설계한다.

- 미성년자 또는 미성년자처럼 보이는 캐릭터에 성적, 연애, 신체 접촉 맥락의 반응을 붙이지 않는다.
- 나이와 설정을 알 수 없는 캐릭터는 기본적으로 `GENERAL` 등급으로 취급한다.
- `loli`, `shota`, `childlike`, `schoolchild` 등 미성년자 코드가 강한 캐릭터는 부적절한 상호작용, 스티커, 대사, 롤플레잉을 금지한다.
- 일반 사용자 대상 기본 상호작용에서 민감 부위 터치, 몸 터치, 수치심을 유도하는 대사, 성적 농담을 제거한다.
- 신고 사유에 "미성년자/어린이 캐릭터 부적절 사용"을 둔다.
- 운영자는 캐릭터 숨김, 삭제, 상호작용 제한, 스티커 제한을 수행할 수 있어야 한다.
- 성인 캐릭터 선언이 있더라도 플랫폼 기본 터치/알림/추천 반응은 비성적이어야 한다.

### 터치 액션 정리 방향

현재 구현에는 `tap_head`, `tap_body`, `tap_other`가 있고, 업로드 모델 자동 매핑에서 `body/chest/torso` 계열 히트 영역이 `tap_body`로 추정된다. 제품 기준으로는 이 구조를 그대로 노출하지 않는다.

- `tap_body`는 신규 제품 액션에서 제거하거나 내부 호환용으로만 남긴다.
- 사용자에게 보이는 액션 이름은 `attention`, `greet`, `cheer`, `thinking`, `celebrate`, `surprised`, `idle`, `typing`처럼 비신체 접촉 중심으로 바꾼다.
- 히트 영역 자동 매핑은 `body/chest/torso`를 민감한 액션으로 연결하지 않고 `attention` 또는 `tap_other`에 해당하는 안전 액션으로 보낸다.
- 기본 대사는 비성적, 비연애, 비수치심, 비신체 접촉 톤으로 교체한다.
- 터치 반응은 핵심 기능이 아니라 보조 입력으로 취급하고, 알림·추천·글쓰기 보조 같은 실제 서비스 이벤트 반응을 우선한다.

## 6. 커뮤니티 이벤트와 Live2D 반응

- 내 글에 댓글이 달리면 캐릭터가 말풍선과 감정 모션으로 반응한다.
- 내 글이 개념글이 되면 축하 모션 또는 메시지를 보여준다.
- 신고/제재 같은 민감 알림은 과장된 연출보다 차분한 안내로 처리한다.
- 사용자가 글을 작성 중일 때 캐릭터가 방해하지 않도록 반응 빈도와 위치를 조절한다.

### 상황별 매핑 기준

크리에이터에게 표정과 액션을 따로 끝없이 등록하게 하지 않는다. 관리 화면의 기본 매핑은 로그인, 로그아웃, 알림 공통, 글쓰기 중, 기본 복귀처럼 서비스에서 실제로 자주 쓰는 상황만 보여주고, 각 상황마다 표정과 모션을 한 번에 선택하게 한다. 댓글/답글/리액션/팔로우/개념글/시스템 알림은 말풍선 텍스트와 추후 사운드는 나눌 수 있지만, 모션은 알림 공통 매핑 하나를 공유한다.

- 모델이 특정 표정이나 모션을 갖고 있지 않으면 해당 칸은 비워도 된다.
- 최초 등록 시에는 자동 표정/모션 추정 결과를 이용해 상황별 추천 매핑을 기본으로 채운다.
- 고급 사용자를 위해 개별 감정/액션 매핑은 접힌 고급 섹션으로 유지한다.
- `[미리보기]`는 매핑 행 바로 옆의 미리보기 모델에 적용되어, 파일명만 보고 고르는 문제를 줄인다.

## 7. 덕질 비서와 안내

캐릭터는 챗봇 앱의 자유 대화 상대가 아니라 10duck 커뮤니티를 쓰기 쉽게 만드는 인터랙티브 가이드다. 채팅창이 있더라도 "아무 말이나 해봐"보다 목적형 액션과 짧은 선택지를 우선한다.

### 우선 기능

- **알림·활동 비서:** 중요 알림과 팔로우 활동을 말풍선으로 요약한다.
- **오늘의 덕질 브리핑:** 팔로우 게시판 인기글, 안 읽은 알림, 오늘의 하이라이트를 요약한다.
- **콘텐츠 추천 도우미:** 관심 태그·시간대·스포일러 허용 여부에 맞춰 볼 만한 글이나 게시판을 추천한다.
- **스포일러 가드:** 작성자가 스포일러 태그 또는 말머리(`[스포]` 등)를 단 글이나 최신화 토론을 열기 전에 캐릭터가 짧게 경고한다. 회차 단위 자동 마스킹·본문 인라인 블러 같은 복잡한 정책은 도입하지 않고, 작성자 자율 표시만을 신호로 사용한다.
- **글쓰기 도우미:** 제목, 말머리, 본문 구성, 스포일러 여부를 질문해 작성을 돕는다.
- **활동·기록 리마인더:** 이어 읽기, 임시저장, 미완료 초안을 상기시킨다.
- **커뮤니티 반응:** 내 글과 댓글에 대한 반응을 과하지 않게 알려준다.

### 상호작용 방식

- 기본은 말풍선, 토스트, 짧은 선택지 버튼 2~4개다.
- 자유 입력창은 추천, 요약, 글쓰기 보조처럼 목적이 분명한 화면에서만 제공한다.
- 답변은 게시판, 알림, 팔로우, 검색 결과처럼 서비스 내부 데이터에 근거해야 한다.
- 사용자의 민감한 활동 이력은 명시적 동의 없이 장기 기억에 넣지 않는다.
- 캐릭터가 스스로 과도하게 말을 걸지 않도록 빈도 제한과 끄기 설정을 제공한다.

### 어시스턴트 슬롯 매트릭스 (2026-05-18 확정)

캐릭터를 탭하면 열리는 어시스턴트 메뉴는 **고정 3슬롯**이지만, 슬롯 내용은 현재 라우트에 따라 달라진다. 기존의 `오늘 일정 / 이번 주 / 새 소식` 3종은 캘린더 거울 역할만 하고, 실제 어디서 눌러도 동일한 응답만 내는 한계가 있었다. 컨텍스트 인식 매트릭스로 전환해 페이지마다 다른 가치를 제공한다.

| 페이지 (라우트) | 슬롯 1 | 슬롯 2 | 슬롯 3 |
|-----------------|--------|--------|--------|
| 홈/피드/게시판 목록/뉴스/알림 (기본) | 오늘 내 활동 요약 | 내 미답글 큐 | 오늘의 미션 |
| 게시글 상세 `/board/[slug]/[id]` | (컨텍스트) 스티커 답글 | 내 미답글 큐 | 오늘의 미션 |
| 글쓰기 `/board/[slug]/write` | (컨텍스트) 임시저장 복귀 | 오늘 내 활동 요약 | 오늘의 미션 |
| 캘린더 `/calendar` | 오늘 일정 | 이번 주 | 관심작 새 소식 |
| 신작 `/releases`, `/season/*` | 오늘 일정 | 이번 주 | 관심작 새 소식 |
| 프로필 / 사용자 페이지 | 오늘 내 활동 요약 | 내 미답글 큐 | 오늘의 미션 |

운영 메모:
- 슬롯 결정은 `lib/assistant/slots.ts`의 `getAssistantSlots(pathname)`에서 라우트 매처로 처리한다.
- 캘린더 거울 액션(오늘 일정 / 이번 주)은 캘린더·신작 라우트에서만 살린다. 다른 곳에서는 보이지 않는다.

### 슬롯별 데이터 정의

각 액션은 짧은 말풍선 응답 + 클릭 시 이동할 URL을 가진다. 응답은 `setTemporaryMessage()`로 4.5초 노출한다.

**오늘 내 활동 요약**
- 데이터 소스: 오늘(현지 자정~지금) 사이에 내가 받은 `post_reactions`(내 글), 내 글의 새 `comments`, 새 `follows_user`.
- 말풍선 예시: `"오늘은 리액션 12, 댓글 3, 새 팔로워 2명 받았어요!"`
- 0건이면: `"아직 새 활동이 없어요. 글 하나 올려볼까요?"`
- 이동: `/user/[내 handle]/activity`.

**내 미답글 큐**
- 데이터 소스: ①내 게시글에 달린 루트 댓글 중, 같은 글에 내가 작성한 후속 댓글이 없는 것 + ②내 댓글에 달린 대댓글 중 내가 답장하지 않은 것 + ③나에게 온 `MENTION` 알림 중 미읽음.
- 말풍선 예시: `"답장 안 한 댓글이 5개 있어요"` (가장 최근 1개 미리보기 글 제목 포함)
- 0건이면: `"답장 다 했어요. 멋져요!"`
- 이동: `/profile?tab=unreplied` (신규 탭) 또는 첫 미답글 게시글로 직행.

**오늘의 미션**
- 데이터 소스: `daily_missions(active=true)` × 사용자의 `user_mission_progress(ymd_key=today)` 조인.
- 1차 운영용 시드 3개: 출석 / 오늘 댓글 1개 / 오늘 추천 3개.
- 진행 카운팅은 댓글 작성, 추천 토글, 캐릭터 탭(출석) 시점에 서버 함수 또는 클라이언트 핸들러에서 `progress_count`를 +1 한다.
- 말풍선 예시: `"오늘의 미션: 출석 ✓ / 댓글 0·1 / 추천 1·3"`
- 이동: `/missions`.

**관심작 새 소식**
- 데이터 소스: 사용자의 `user_release_follows`와 연결된 `release_events` 중 최근 24시간 변경 사항 + 관심 태그가 일치하는 최신 `news_items`.
- 말풍선 예시: `"별빛 학원 2기 방영이 D-3로 다가왔어요"`
- 이동: `/releases` 또는 해당 release 상세.

**컨텍스트 액션**
- **스티커 답글:** 게시글 상세에서 활성 캐릭터의 `idle` 또는 `happy` 스티커를 1탭으로 댓글에 등록. 입력 키보드를 꺼내지 않아도 동작하도록 모바일에서 우선 검증한다.
- **임시저장 복귀:** 글쓰기 페이지 진입 시 같은 게시판의 미게시 임시저장 글이 있으면 1탭으로 복귀. 없으면 슬롯 자체가 비활성화된다.

### 페이지별 대사 프리셋

새 페이지를 추가할 때는 화면 자체뿐 아니라 Live2D 캐릭터가 그 페이지에서 말할 기본 대사도 함께 정의한다. 페이지 이동 직후 짧게 뜨는 대사는 사용자가 지금 화면에서 무엇을 할 수 있는지 알려주는 안내 역할만 해야 하며, 광고성 문구나 과한 감정 표현은 피한다.

페이지 추가 시 같이 확인할 것:

- `Live2DWrapper`의 페이지 경로별 대사 프리셋에 새 경로를 추가한다.
- 대사는 1~2문장, 3~4초 안에 사라지는 짧은 안내로 작성한다.
- 글쓰기, 프로필, 관리 화면처럼 목적이 다른 페이지는 서로 다른 톤을 둔다.
- 캐릭터 관리 화면에는 페이지별 대사 프리셋을 수정할 수 있는 입력 영역을 추가하는 방향으로 확장한다.
- 실제 모델에 없는 감정/모션에 연결된 대사 입력칸은 빨간 보더로 표시해, 입력해도 런타임에서 표정/모션이 동작하지 않을 수 있음을 보여준다.
- 페이지별 대사는 자유 대화가 아니라 화면 맥락 안내이므로 개인정보, 민감 활동 이력, 성적/연애 맥락을 포함하지 않는다.

## 8. 후순위 AI 롤플레잉 확장

동료 니즈를 반영해 롤플레잉 채팅은 장기 확장 후보로 남긴다. 다만 초기 제품의 중심은 커뮤니티와 목적형 덕질 비서이며, 롤플레잉은 별도 안전 정책과 성숙한 운영 도구가 갖춰진 뒤 검토한다.

- 지시문 기반 1:1 롤플레잉 채팅 UI는 Phase 4 이후 후순위로 검토한다.
- 캐릭터별 페르소나, 말투, 관계 상태, 장기 기억을 설계할 수 있다.
- 롤플레잉은 미성년자/어린이처럼 보이는 캐릭터, 성적 맥락, 강한 의존 유도, 개인정보 기억에 대해 별도 제한을 둔다.
- 커뮤니티 활동 이력 일부가 캐릭터 기억에 반영될지 정책을 정한다.
- 개인정보와 민감한 커뮤니티 활동은 명시적 동의 없이 장기 기억에 넣지 않는다.
- 롤플레잉 기능은 추천·알림·글쓰기 보조와 분리해 끄거나 숨길 수 있어야 한다.
