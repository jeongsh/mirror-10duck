# 씹덕 제품 브리프

`씹덕`은 서브컬처 사용자가 글을 쓰고, 반응하고, 좋아하는 작품과 캐릭터를 드러내고, 일정과 소식을 따라가며 다시 돌아오는 커뮤니티 허브를 목표로 한다. 현재 구현된 기반 위에 창작, 굿즈, 캐릭터, 시즌패스, 유료 콘텐츠까지 확장할 수 있는 제품이다.

## 1. 한 장 요약

### 제품 한 줄 정의

`씹덕`은 애니, 만화, 게임, 캐릭터, 창작, 굿즈, 팬덤 활동을 한곳에 모아 커뮤니티 활동과 개인 덕질 기록, 캐릭터 연출, 시즌형 리텐션, 유료 콘텐츠 소비까지 연결하는 한국어 서브컬처 허브다.

### 핵심 방향

- 시작점은 게시판형 커뮤니티다. 사용자는 글을 보고, 쓰고, 댓글을 달고, 추천하고, 팔로우하고, 알림으로 돌아온다.
- 차별점은 덕질 맥락이다. 일반 커뮤니티가 아니라 오시 등록, 배지, 뉴스, 신작 일정, 굿즈 컬렉션, 창작자 트랙, Live2D 캐릭터, 시즌패스가 연결된다.
- 수익화는 결제 버튼만 붙이는 방식이 아니다. 광고 제거, 토큰, 캐릭터 슬롯, 시즌패스, 유료 웹툰/소설, 창작자 후원, 굿즈/거래 보조 같은 구조가 커뮤니티 활동과 자연스럽게 이어져야 한다.
- 안전과 운영 정책이 제품 신뢰의 핵심이다. 미디어 업로드, 성인/NSFW, 미성년자 캐릭터, 거래, 채팅, 가챠, 다국어 확장은 모두 운영 정책 없이는 열면 안 된다.

### 지금 제품에 필요한 정리

지금 필요한 것은 새 기능을 더 늘리는 것보다, 이미 있는 기반과 앞으로의 확장 후보를 제품 흐름 안에 배치하는 일이다.

- 1차 출시 정체성: 커뮤니티 허브를 중심에 둘지, 창작/캐릭터/유료 콘텐츠 중 일부를 전면에 올릴지 정한다.
- 정보 구조: 게시판, 피드, 뉴스, 캘린더, 프로필, 캐릭터, 창작자, 굿즈, 상점의 관계를 정리한다.
- 마감 범위: 이미 구현된 기능 중 출시 전에 다듬을 것과 후순위로 미룰 것을 분리한다.
- 운영 기준: 신고, 인증, 미디어 검수, 거래, 가챠, 유료 콘텐츠, 다국어 운영의 최소 기준을 둔다.
- 화면 흐름: 사용자가 처음 들어와서 탐색, 참여, 팔로우, 알림, 재방문으로 이어지는 흐름을 명확히 한다.

## 2. 제품 정체성

### 2.1 기본 정체성: 커뮤니티 허브

가장 기본적인 정체성은 서브컬처 커뮤니티다. 사용자는 애니, 만화, 게임, 캐릭터, V, 굿즈, 창작물에 대해 게시판과 피드에서 이야기한다.

필수 경험은 다음과 같다.

- 관심 있는 게시판이나 피드에 들어간다.
- 글 목록에서 게시판 맥락, 작성자 신원, 조회수, 댓글 수, 추천 수, 개념글 여부를 빠르게 판단한다.
- 글을 쓰고, 댓글을 달고, 추천/비추천 또는 감정 리액션을 남긴다.
- 마음에 드는 사용자나 게시판을 팔로우한다.
- 댓글, 답글, 리액션, 팔로우, 개념글 알림을 받고 다시 돌아온다.

이 루프가 살아 있어야 이후 기능들이 의미를 가진다. 창작자 트랙, 유료 콘텐츠, 캐릭터, 시즌패스도 결국 커뮤니티 활동으로 다시 돌아와야 한다.

### 2.2 덕질 정체성: 좋아하는 것을 드러내는 서비스

일반 커뮤니티와 다르게 이 서비스는 사용자가 "무엇을 좋아하는 사람인지"를 드러내야 한다.

- 오시 등록: 사용자가 최애 작품/캐릭터를 최대 5개 등록한다.
- 배지: 사용자의 활동 이력을 프로필 장식으로 보여준다.
- 대표 캐릭터: 계정의 시각적 서명처럼 동작한다.
- 관심작: 뉴스, 캘린더, 알림과 연결되는 개인 덕질 기준점이다.
- 굿즈 컬렉션: 소장품과 위시리스트로 취향과 애착을 표현한다.

이 정체성은 팔로우 이유와 대화 이유를 만든다. 단순 닉네임만으로는 사용자가 서로를 기억하기 어렵지만, 오시, 배지, 캐릭터, 컬렉션은 관계 형성의 단서가 된다.

### 2.3 캐릭터 정체성: 장식이 아니라 인터랙션 레이어

Live2D 캐릭터는 제품의 중심 기능이라기보다, 커뮤니티 경험 위에 올라가는 인터랙션 레이어다.

- 알림을 말풍선으로 알려준다.
- 페이지 맥락에 맞는 짧은 안내를 한다.
- 글쓰기, 알림, 뉴스, 오늘 일정 같은 목적형 행동을 돕는다.
- 스티커와 리액션을 통해 커뮤니티 밈을 만든다.
- 장기적으로는 자체 캐릭터, 시즌 캐릭터, 캐릭터 슬롯, 캐릭터 상점, 캐릭터 의뢰 마켓, 캐릭터 가챠, 페르소나 챗으로 확장될 수 있다.

초기에는 자유 대화형 캐릭터 AI보다 커뮤니티 사용을 돕는 덕질 비서가 우선이다. 캐릭터 페르소나 챗을 메인으로 올릴지는 별도 전략 결정이 필요하다.

### 2.4 콘텐츠 정체성: 소비와 창작이 같이 있는 구조

장기적으로는 게시글만 있는 커뮤니티를 넘어 창작자 트랙과 유료 웹툰/소설까지 확장할 수 있다.

- 창작자는 일러스트, 소설, 만화, 웹툰을 게시판 글이 아닌 작품 단위로 올린다.
- 사용자는 창작자 프로필, 작품 갤러리, 시리즈, 후원, 코미션 안내를 본다.
- 유료 웹툰/소설은 토큰 기반 회차 열람, 무료 회차, 미리보기, 성인 인증, 정산 정책이 필요하다.
- 창작자 트랙은 커뮤니티의 하위 게시판이 아니라 별도 UX가 필요하다.

이 축을 채택하면 서비스는 "커뮤니티 + 창작 플랫폼"의 듀얼 정체성을 가진다.

### 2.5 리텐션 정체성: 시즌마다 돌아올 이유를 만드는 서비스

배지는 정적 보상이다. 시즌패스는 사용자가 매일 또는 매주 돌아올 이유를 만든다.

- 출석, 글쓰기, 댓글, 추천, 오시 등록, 관심작 알림, 시즌 신작 감상 같은 행동으로 미션을 진행한다.
- 보상은 토큰, 배지, 시즌 캐릭터, 캐릭터 의상, 스티커, 가챠 뽑기권, 프로필 장식이 될 수 있다.
- 시즌은 애니 분기, 게임 이벤트, 커뮤니티 행사와 연결할 수 있다.
- 과도한 도파민 설계나 도배 유도는 피하고, 활동 상한과 어뷰징 방지 정책을 둔다.

## 3. 핵심 사용자

### 3.1 커뮤니티 참여자

글을 읽고 쓰는 기본 사용자다. 빠른 게시판 탐색, 익명/닉네임 선택, 댓글, 추천, 알림, 차단, 신고, 모바일 UX가 중요하다.

필요한 화면:

- 홈 또는 피드
- 게시판 목록
- 게시글 목록
- 게시글 상세
- 글쓰기
- 댓글/대댓글
- 알림
- 프로필

### 3.2 덕질 기록형 사용자

자신이 좋아하는 작품, 캐릭터, 굿즈, 관심작을 기록하고 보여주고 싶어 한다.

필요한 화면:

- 오시 등록
- 배지
- 관심작 관리
- 덕질 캘린더
- 굿즈 컬렉션
- 위시리스트
- 공개 프로필

### 3.3 창작자

그림, 소설, 만화, 웹툰, 스티커, 캐릭터 에셋을 올리고 팬을 모으고 싶어 한다.

필요한 화면:

- 창작자 프로필
- 작품 업로드
- 작품 갤러리
- 시리즈 관리
- 유료 회차 관리
- 후원/코미션 안내
- 정산 대시보드
- 신고/저작권 대응

### 3.4 캐릭터 중심 사용자

Live2D, 자체 캐릭터, 페르소나, 스티커, 캐릭터 슬롯, 가챠, 시즌 캐릭터에 반응하는 사용자다.

필요한 화면:

- 캐릭터 라이브러리
- 대표 캐릭터 설정
- 캐릭터 슬롯 관리
- 스티커 관리
- 캐릭터 상점
- 캐릭터 의뢰 마켓
- 시즌 캐릭터 보상
- 페르소나 챗 또는 목적형 덕질 비서

### 3.5 수집형 사용자

굿즈, 피규어, 단행본, 블루레이, 동인지, 한정판을 모으고 기록하고 싶어 한다.

필요한 화면:

- 굿즈 검색/등록
- 내 컬렉션
- 위시리스트
- 인증 사진
- 발매 알림
- 컬렉션 배지
- 향후 거래 전용 채팅

### 3.6 운영자

커뮤니티 품질, 안전, 결제, 창작물, 거래, 가챠, 신고를 관리해야 한다.

필요한 화면:

- 게시판 관리
- 게시글/댓글 신고 큐
- 사용자 제재
- 이미지 검수 큐
- 뉴스/일정 관리
- 창작물 검수
- 유료 콘텐츠 관리
- 거래/분쟁 관리
- 가챠/확률/보상 관리
- 운영 로그

## 4. 전체 제품 구조

### 4.1 메인 루프

```
탐색 → 게시글/콘텐츠 소비 → 반응 → 팔로우/관심 등록 → 알림 → 재방문
```

이 루프는 모든 기능의 공통 기반이다.

- 게시판은 대화의 중심이다.
- 피드는 팔로우 관계를 강화한다.
- 뉴스와 캘린더는 들어올 이유를 만든다.
- 오시와 배지는 사용자의 정체성을 만든다.
- Live2D는 알림과 안내를 감정적으로 전달한다.
- 시즌패스는 반복 방문을 구조화한다.
- 창작자와 유료 콘텐츠는 결제와 팬덤을 만든다.

### 4.2 정보 구조 초안

| 상위 영역 | 역할 | 주요 기능 |
|---|---|---|
| 홈/피드 | 매일 보는 입구 | 추천 글, 팔로우 글, 개념글, 뉴스, 오늘 일정 |
| 게시판 | 커뮤니티 대화 | 글 목록, 글 상세, 댓글, 추천, 신고, 검색 |
| 글쓰기 | 참여 생성 | 에디터, 이미지, 영상 임베드, 스티커, 임시저장 |
| 프로필 | 사용자 정체성 | 닉네임, 아바타, 대표 캐릭터, 오시, 배지, 활동 |
| 캐릭터 | 제품 차별화 | Live2D, 캐릭터 슬롯, 스티커, 시즌 캐릭터, 캐릭터 상점, 캐릭터 의뢰, 가챠 |
| 뉴스 | 자체 뉴스 서비스와 토론 연결 | 애니/만화/게임 뉴스 기사, 카테고리, 태그, 토론글 |
| 캘린더 | 덕질 일정 | 방영, 연재, 출시, 이벤트, 관심작 알림 |
| 창작 | 장기 성장축 | 작품 갤러리, 웹툰/소설, 후원, 코미션 |
| 굿즈 | 수집 성장축 | 컬렉션, 위시리스트, 인증, 발매 알림 |
| 시즌패스 | 리텐션 | 데일리 미션, 분기 챌린지, 배지, 토큰, 보상 |
| 상점/구독 | 수익화 | 광고 제거, 토큰, 슬롯, 유료 콘텐츠, 가챠 |
| 운영자 | 안전과 품질 | 신고, 검수, 제재, 뉴스/일정, 결제/정산 |

## 5. 기능별 상세 기획

### 5.1 커뮤니티 기본 기능

목표는 사용자가 "커뮤니티답다"고 느끼는 최소 루프를 완성하는 것이다.

주요 기능:

- 게시판 목록과 게시판별 글 목록
- 게시글 상세
- 글쓰기와 수정/삭제
- 댓글과 1단 대댓글
- 추천/비추천
- 감정 리액션
- 개념글
- 게시판 검색, 정렬, 말머리
- 사용자 팔로우와 게시판 팔로우
- 팔로우 기반 피드
- 크로스포스트
- 신고, 차단, 숨김
- 알림

기획 포인트:

- 글 목록의 정보 밀도가 중요하다. 작성자 신원, 게시판, 말머리, 댓글 수, 추천 수, 조회 수, 개념글 여부가 한눈에 보여야 한다.
- 익명, 비고정닉, 고정닉 정책은 사용자가 글을 쓸 때 바로 이해할 수 있어야 한다.
- 추천과 개념글은 커뮤니티 분위기를 결정하므로 기준과 어뷰징 방지 정책이 필요하다.
- 신고와 차단은 숨겨진 운영 기능이 아니라 사용자가 신뢰를 느끼는 안전 장치다.

현재 상태:

- 구현됨: 게시판, 글, 댓글, 1단 대댓글, 추천/비추천, 감정 리액션, 개념글, 피드, 팔로우, 크로스포스트, 차단, 주요 알림
- 진행 중: 운영자 권한, 운영 로그, 레이트 리밋, 신고 자동 블라인드, 성인/NSFW 정책
- 앞으로 필요: 모바일 최적화, 검색 품질, 커뮤니티 온보딩, 정책 문구 정리

### 5.2 프로필, 신원, 오시, 배지

목표는 사용자가 서로를 기억할 수 있는 정체성 시스템을 만드는 것이다.

주요 기능:

- 닉네임과 아바타
- 고정닉/비고정닉/익명 표시 정책
- 대표 캐릭터
- 오시 등록 최대 5개
- 활동 배지 9종
- 공개 프로필
- 팔로우 관계
- 인증 회원 배지

기획 포인트:

- 프로필은 단순 설정 화면이 아니라 "이 사람이 어떤 덕후인지" 보여주는 페이지다.
- 오시는 팔로우 추천, 관심작 알림, 시즌 미션, 배지, 게시판 추천과 연결되어야 한다.
- 인증 회원은 거래, 창작자, 성인 콘텐츠, 유료 콘텐츠, 공식 계정에 따라 등급을 나눌 수 있다.
- 회원정보 찾기, SNS 연동 가입, 계정 복구는 장기 운영에서 필수 인프라다.

현재 상태:

- 구현됨: 프로필, profiles 테이블, 고정닉 유일성, 비고정닉 표시, 비로그인 일회용 닉네임/비밀번호 작성, 오시 등록, 배지, 공개 프로필 표시
- 진행 중: 오시 기반 추천, 시즌 한정 배지
- 앞으로 필요: 인증 회원 정책, SNS 가입/연동, 회원정보 찾기, 계정 복구, 프로필 디자인 체계

### 5.3 에디터, 미디어, 스티커

목표는 커뮤니티 글쓰기를 일반 텍스트에서 이미지, 영상, 스티커가 섞인 서브컬처형 표현으로 확장하는 것이다.

주요 기능:

- 텍스트 에디터
- Tiptap 기반 블록 JSON 저장
- 이미지 업로드와 본문 삽입
- 유튜브 임베드
- 스티커 토큰 삽입과 렌더링
- 스티커-only 댓글
- 임시저장과 이탈 방지

기획 포인트:

- 에디터는 복잡하면 안 된다. 게시판 글쓰기의 속도와 창작물 업로드의 정교함을 분리해야 한다.
- 일반 게시글의 이미지 첨부와 창작자 트랙의 작품 업로드는 다른 UX로 설계해야 한다.
- 스티커는 캐릭터 시스템과 커뮤니티 밈을 연결하는 핵심 에셋이다.
- NSFW와 아청법 위험 대응은 이미지 업로드 설계의 일부로 포함되어야 한다.

현재 상태:

- 구현됨: 텍스트 에디터, 블록 JSON 저장, 이미지 삽입, 유튜브 임베드, 스티커 삽입/렌더링, 작성 중 스티커 미리보기
- 진행 중: 임시저장과 이탈 방지 일부
- 앞으로 필요: 비공개 검역 저장소, 승인 후 공개 승격, AI 위험 태그 검수, 해시 기반 중복 검수 캐시, 차단 해시 목록

### 5.4 뉴스, 신작, 캘린더

목표는 사용자가 매일 들어올 이유를 만드는 것이다.

주요 기능:

- 애니/만화/게임 뉴스
- 기사 본문, 썸네일, 카테고리, 태그
- 신작 일정 카드
- 방영/연재/출시 이벤트
- 관심작 등록
- 캘린더
- 관심작 기반 알림
- 뉴스에서 토론글 쓰기

기획 포인트:

- 이 서비스는 깊은 작품 DB를 직접 운영하지 않는다. 뉴스와 일정은 커뮤니티 활동으로 연결되는 자체 편집 정보와 일정 정보다.
- 애니, 만화, 게임은 상위 입구에서는 같이 보여주되 내부 일정 문법은 분리한다.
- 뉴스는 외부 기사 링크를 모아두는 곳이 아니라 운영자가 직접 작성·편집하는 자체 뉴스 서비스다.
- 캘린더는 복잡한 개인 일정 앱이 아니라 관심작과 공식/운영자 일정이 모이는 보조 화면이다.

현재 상태:

- 구현됨: 뉴스 탭 구조와 자체 기사 저장 정책 1차, release_items, release_events, user_release_follows, 캘린더 월 그리드, 관심 작품 알림 토글 1차
- 진행 중: Live2D 오늘/이번 주 일정 말풍선, 관심작 알림 세부 UI, 개인 일정
- 앞으로 필요: 뉴스 카드에서 관련 게시판/토론글/스크랩/태그 알림 연결, 오늘 방영 목록에서 감상글 보기/글쓰기/채널 이동, 푸시 알림

### 5.5 Live2D, 자체 캐릭터, 캐릭터 슬롯

목표는 캐릭터를 단순 장식이 아니라 커뮤니티 사용을 돕는 브랜드 경험으로 만드는 것이다.

주요 기능:

- 전역 Live2D 캐릭터
- 캐릭터 라이브러리
- 업로드 캐릭터
- 대표 캐릭터
- 페이지별 대사
- 알림 말풍선
- 감정 상태/모션
- 캐릭터 슬롯
- 시즌 캐릭터
- 캐릭터 유료화
- 캐릭터 상점
- 캐릭터 의뢰 마켓
- 캐릭터 가챠

기획 포인트:

- "우리만의 캐릭터"는 서비스 브랜드 자산이 될 수 있다. 기본 마스코트, 시즌 캐릭터, 이벤트 캐릭터를 운영할 수 있다.
- 캐릭터 슬롯은 구독 또는 토큰 결제와 연결하기 쉽다.
- 캐릭터 상점은 운영자가 제공하는 캐릭터, 스킨, 의상, 스티커, 시즌 보상을 판매하거나 배포하는 공간이다.
- 캐릭터 의뢰 마켓은 사용자가 창작자에게 Live2D 모델, 캐릭터 일러스트, 리깅, 스티커 제작을 의뢰하는 크몽형 거래 영역이다. 상점과 달리 견적, 작업 범위, 수정 횟수, 납기, 검수, 분쟁 조정, 정산 정책이 필요하다.
- 캐릭터 가챠는 강한 수익화 요소지만 확률 표시, 미성년자 결제, 환불, 사행성, 환금성 제한 정책이 필요하다.
- 캐릭터 페르소나 챗은 메인 정체성으로 올릴지 후순위로 둘지 결정해야 한다.
- 미성년자처럼 보이는 캐릭터, 성적 맥락, 신체 접촉형 상호작용은 안전 정책상 엄격히 제한해야 한다.

현재 상태:

- 구현됨: 전역 Live2D 렌더링, 캐릭터 라이브러리와 업로드, 페이지별 대사, 알림 말풍선, 터치 액션 안전화 일부, 대표 캐릭터 공개 프로필
- 진행 중: 알림/활동 비서, 글쓰기 도우미, 스티커 관리, 캐릭터 커뮤니티 반응
- 앞으로 필요: 캐릭터 슬롯 정책, 자체 캐릭터 운영, 시즌 캐릭터, 캐릭터 상점, 캐릭터 의뢰 마켓, 가챠 정책, 캐릭터 페르소나 챗 전략 결정

### 5.6 창작자 트랙

목표는 게시판 글과 다른 창작물 소비 UX를 만드는 것이다.

주요 기능:

- 창작자 프로필
- 작품 갤러리
- 일러스트, 소설, 만화, 웹툰 업로드
- 시리즈 관리
- 회차형 콘텐츠
- 무료/유료 회차
- 후원 또는 팬클럽
- 코미션 안내
- 창작자 인증

기획 포인트:

- 창작자 트랙은 게시판의 말머리만으로 해결하면 안 된다.
- 작품 상세 페이지, 시리즈 페이지, 작가 페이지, 회차 목록, 댓글/감상, 북마크가 필요하다.
- AI 생성물 표시, 저작권, 펌금, NSFW, 성인 인증 정책이 먼저 필요하다.
- 유료 웹툰/소설까지 연결하면 결제, 토큰, 정산, 환불, 신고, 미성년자 보호 정책이 필요하다.

현재 상태:

- 구현됨: 일반 게시글과 미디어 업로드 기반은 존재
- 진행 중: 없음
- 앞으로 필요: 창작자 트랙 IA, 작품 업로드 UX, 웹툰/소설 페이지, 창작자 인증, 유료 회차, 정산 정책

### 5.7 캐릭터 의뢰 거래 시스템

목표는 캐릭터 관련 맞춤 제작을 사용자와 창작자 사이의 거래로 연결하는 것이다.

주요 기능:

- 창작자 포트폴리오
- 의뢰 상품 등록
- Live2D 모델 의뢰
- 캐릭터 일러스트 의뢰
- 리깅 의뢰
- 스티커/프로필 카드 의뢰
- 견적 요청과 협의
- 작업 진행 상태
- 결과물 검수와 수정 요청
- 완료 확정과 리뷰
- 분쟁/환불/정산

기획 포인트:

- 캐릭터 의뢰는 캐릭터 상점과 분리해야 한다. 상점은 운영자가 준비한 캐릭터/스킨/의상을 판매하는 구조이고, 의뢰는 사용자와 창작자 사이의 맞춤 제작 거래다.
- 크몽형 거래 구조가 필요하다. 상품 상세, 포트폴리오, 가격, 작업 범위, 수정 횟수, 납기, 결제 보호, 완료 확정, 리뷰가 있어야 한다.
- 파일 소유권, 상업적 이용권, 2차 수정 가능 여부, 원본 파일 제공 여부를 결제 전에 명확히 표시해야 한다.
- Live2D 모델은 일러스트보다 작업 범위가 복잡하므로 모델링, 파츠 분리, 리깅, 표정/모션, 테스트 범위를 나눠야 한다.
- 분쟁이 생기기 쉬운 영역이므로 신고, 중재, 환불, 정산 보류, 창작자 제재 정책이 필요하다.

현재 상태:

- 구현됨: 일반 캐릭터 업로드와 라이브러리 기반은 존재
- 진행 중: 없음
- 앞으로 필요: 의뢰 마켓 IA, 창작자 인증, 상품 등록, 견적/결제/검수 플로우, 파일 권리 정책, 분쟁/정산 정책

### 5.8 굿즈 컬렉션과 위시리스트

목표는 거래 이전에 "내가 가진 것과 사고 싶은 것"을 기록하고 자랑하는 수집형 행동을 만드는 것이다.

주요 기능:

- 굿즈 등록
- 보유 컬렉션
- 위시리스트
- 인증 사진
- 친구 컬렉션 보기
- 굿즈 발매 알림
- 컬렉션 배지
- 향후 거래 전용 채팅

기획 포인트:

- 처음부터 거래를 열면 사기, 미성년자 거래, 분쟁, 개인정보 문제가 커진다.
- 1차는 거래 없는 수집 트래커로 시작하는 것이 안전하다.
- 거래를 열 경우 인증 회원, 거래 닉네임, 전용 채팅, 신고/분쟁, 차단, 운영자 개입, 거래 기록 보관이 필요하다.
- 거래용 포인트나 토큰을 사용하면 전자금융, 환불, 환금성, 정산 정책 검토가 필요하다.

현재 상태:

- 구현됨: 관련 기능 없음
- 진행 중: 캘린더와 발매 알림 구조 일부가 향후 연결 가능
- 앞으로 필요: 굿즈 메타데이터, 컬렉션 UX, 위시리스트, 인증, 거래 정책

### 5.9 시즌패스, 미션, 가챠

목표는 사용자가 시즌마다 돌아오고 활동하도록 만드는 것이다.

주요 기능:

- 시즌패스
- 데일리/위클리 미션
- 분기 챌린지
- 시즌 배지
- 시즌 캐릭터
- 토큰 보상
- 캐릭터 의상 또는 스티커 보상
- 가챠 뽑기권

기획 포인트:

- 미션은 커뮤니티 품질을 해치면 안 된다. 도배를 유도하는 "글 10개 작성"보다 좋은 글, 댓글, 관심작, 출석, 감상 기록처럼 건강한 행동을 설계해야 한다.
- 보상은 경제 밸런스가 필요하다. 토큰을 너무 많이 주면 결제 가치가 떨어지고, 너무 적으면 시즌패스 가치가 약하다.
- 가챠는 확률, 중복 보상, 천장, 환불, 미성년자 결제 제한, 확률 공개가 필요하다.
- 시즌패스는 배지 시스템과 캐릭터 시스템을 연결할 수 있는 핵심 리텐션 장치다.

현재 상태:

- 구현됨: 정적 배지 기반
- 진행 중: 시즌 한정 배지 아이디어
- 앞으로 필요: 시즌 구조, 미션 정책, 보상 경제, 가챠 정책, 상점/구독 연결

### 5.10 구독, 토큰, 유료화

목표는 커뮤니티 신뢰를 해치지 않으면서 장기 운영비와 콘텐츠 비용을 회수하는 것이다.

구독/결제 후보:

- 광고 제거
- 월간 토큰 지급
- 캐릭터 슬롯 추가
- 캐릭터 스킨/의상
- 캐릭터 의뢰 중개 수수료
- 시즌패스 프리미엄 보상
- 유료 웹툰/소설 열람
- 창작자 후원
- 스티커/캐릭터 에셋 구매
- 커뮤니티 부스팅

권장 단계:

| 단계 | 상품 | 설명 |
|---|---|---|
| 무료 | 기본 커뮤니티 | 게시판, 댓글, 추천, 기본 프로필, 제한된 캐릭터 슬롯 |
| 라이트 구독 | 광고 제거 + 편의 | 광고 제거, 추가 저장공간, 알림/프로필 편의, 소량 토큰 |
| 팬 구독 | 캐릭터/시즌 강화 | 캐릭터 슬롯, 시즌패스 보너스, 스티커/장식 |
| 토큰 충전 | 소비형 결제 | 유료 회차, 캐릭터/스티커, 가챠권, 후원 |
| 창작자 결제 | 콘텐츠 경제 | 유료 웹툰/소설, 후원, 캐릭터 의뢰, 코미션 연결, 정산 |

기획 포인트:

- 토큰은 서비스 내부 소비 수단으로 설계하되 환금성 여부를 명확히 해야 한다.
- 거래용 포인트와 콘텐츠 구매용 토큰은 분리하는 것이 안전할 수 있다.
- 유료 콘텐츠는 미리보기, 무료 회차, 결제 전 확인, 환불/청약철회 안내가 필요하다.
- 캐릭터 의뢰는 디지털 상품 구매보다 분쟁 가능성이 높다. 작업 범위, 수정 횟수, 납기, 파일 소유권, 상업적 이용권, 환불 기준을 결제 전에 명확히 보여줘야 한다.
- 광고 제거는 가장 단순한 구독 혜택이지만 단독으로는 매력이 약하므로 캐릭터, 시즌, 토큰과 묶어야 한다.

현재 상태:

- 구현됨: 결제/구독 기능 없음
- 진행 중: 수익화 아이디어 정리 단계
- 앞으로 필요: 상품 구조, 가격, 토큰 경제, 캐릭터 의뢰 거래 정책, 결제 PG, 환불, 정산, 회계/세무, 미성년자 결제 정책

### 5.11 캐릭터 페르소나 챗

목표는 캐릭터와의 1:1 대화가 제품의 메인 정체성이 될 수 있는지 판단하는 것이다.

가능한 기능:

- 최애 캐릭터, 자체 캐릭터, V, 오리지널 페르소나와 채팅
- 사용자 제작 페르소나 공유
- 인기 페르소나 랭킹
- 페르소나 기반 커뮤니티
- 시즌 캐릭터와 대화
- 유료 캐릭터 또는 프리미엄 대화량

기획 포인트:

- 이 기능을 메인으로 올리면 서비스 정의가 "커뮤니티 + 캐릭터 AI"로 바뀐다.
- 운영 비용과 추론 비용이 크다.
- 미성년자 캐릭터, 성적 대화, 의존성, 개인정보 기억, 저작권 캐릭터 사용 정책이 필요하다.
- 현재 제품 방향은 목적형 덕질 비서가 우선이고, 자유 롤플레잉은 후순위다.

현재 상태:

- 구현됨: 자유 대화형 챗은 없음
- 진행 중: Live2D 말풍선과 목적형 안내
- 앞으로 필요: 메인화 여부 결정, 안전 정책, 비용 모델, 캐릭터 권리 정책

### 5.12 다국어와 해외 팬 연결

목표는 한국어 커뮤니티를 기반으로 해외 팬덤 콘텐츠와 사용자를 연결하는 것이다.

가능한 기능:

- 일본 공식 트윗/뉴스 번역 큐레이션
- 해외 인기 팬아트/이슈 소개
- 한국어 글의 영어/일본어 번역 보기
- 다국어 댓글 교환
- 해외 팬과 같은 작품 토론
- 글로벌 창작자/팬 프로필

기획 포인트:

- 다국어는 단순 번역 버튼이 아니라 운영 범위 확장이다.
- 저작권과 외부 콘텐츠 인용 정책이 필요하다.
- 일본어/영어 신고, 욕설, 혐오, 스팸 대응이 필요하다.
- 국내 커뮤니티 정체성이 흐려질 수 있으므로 별도 탭 또는 별도 영역으로 시작하는 것이 안전하다.

현재 상태:

- 구현됨: 없음
- 진행 중: 없음
- 앞으로 필요: 번역 품질, 콘텐츠 인용 정책, 다국어 모더레이션, 언어별 UX

## 7. 제품 로드맵 제안

### 7.1 1단계: 기존 구현 기능을 제품답게 마감

목표는 "이미 만들었지만 정리되지 않은 기능"을 실제 사용자에게 보여줄 수 있는 수준으로 다듬는 것이다.

우선순위:

1. 신원과 프로필 정책 마감
2. 게시판/글/댓글 UX 밀도 정리
3. 신고, 차단, 숨김, 운영자 로그 마감
4. 레이트 리밋과 어뷰징 방지
5. NSFW/아청법 위험 대응 정책과 검수 파이프라인
6. 알림과 Live2D 말풍선 빈도 조절
7. 모바일 화면 품질 점검

정리하면 좋은 항목:

- 페이지별 사용자 흐름
- 게시판/프로필/알림 정책 기준
- 운영자 액션 정의
- 신고 사유와 처리 상태 정의
- 화면별 완료 기준

### 7.2 2단계: 덕질 허브 강화

목표는 커뮤니티에 매일 들어올 이유를 만드는 것이다.

우선순위:

1. 뉴스 카드에서 토론글 쓰기 연결
2. 캘린더의 관심작 알림 완성
3. 오늘 방영/연재/출시 화면 정리
4. 오시 기반 추천과 관심작 연결
5. Live2D 오늘의 덕질 브리핑 정리

정리하면 좋은 항목:

- 뉴스 카드 UX
- 신작/일정 카드 UX
- 관심작 알림 플로우
- 덕질 브리핑 문구 규칙
- GNB와 홈 화면 정보 구조

### 7.3 3단계: 리텐션과 수익화 설계

목표는 시즌패스, 토큰, 구독, 캐릭터 슬롯, 캐릭터 의뢰를 하나의 경제 구조로 설계하는 것이다.

우선순위:

1. 무료/구독/토큰 상품 구분
2. 광고 제거 구독의 가치 설계
3. 캐릭터 슬롯과 시즌 캐릭터 설계
4. 캐릭터 의뢰 마켓을 상점과 분리할지 결정
5. 데일리/위클리 미션 설계
6. 시즌패스 보상 테이블 설계
7. 가챠를 도입할지 여부 결정

정리하면 좋은 항목:

- 상품표
- 시즌패스 미션표
- 보상 경제표
- 토큰 사용처
- 캐릭터 의뢰 거래 플로우
- 결제/환불/미성년자 정책

### 7.4 4단계: 창작자와 유료 콘텐츠 확장

목표는 창작자 트랙과 웹툰/소설 페이지를 커뮤니티와 분리된 UX로 설계하는 것이다.

우선순위:

1. 창작자 프로필
2. 작품 페이지
3. 시리즈/회차 구조
4. 웹툰/소설 뷰어
5. 무료/유료 회차 정책
6. 후원/코미션/팬클럽 정책
7. 창작자 정산 정책

정리하면 좋은 항목:

- 창작자 트랙 IA
- 작품 업로드 플로우

우선순위:

5. 다국어 번역 큐레이션 검토

정리하면 좋은 항목:

- 컬렉션/위시리스트 UX
- 인증 회원 정책
- 거래 위험 분석
- 다국어 운영 범위
- 해외 콘텐츠 인용 가이드

## 8. 디자이너가 알아야 할 UX 방향

### 8.1 전체 톤

이 서비스는 일반적인 SaaS나 포트폴리오 사이트처럼 깔끔하기만 해서는 안 된다. 서브컬처 커뮤니티답게 정보 밀도, 캐릭터성, 밈, 활동감이 있어야 한다. 다만 과한 장식으로 게시글 가독성을 해치면 안 된다.

권장 방향:

- 게시판과 글 목록은 정보 밀도를 높인다.
- 프로필, 오시, 배지, 캐릭터 영역은 시각적 개성을 준다.
- 뉴스와 캘린더는 카드형으로 빠르게 읽히게 만든다.
- Live2D는 방해가 아니라 보조 레이어로 보이게 한다.
- 유료화 화면은 신뢰와 투명성을 우선한다.

### 8.2 핵심 화면별 설계 포인트

| 화면 | 설계 포인트 |
|---|---|
| 홈 | 오늘 볼 것, 인기 글, 팔로우 글, 뉴스, 관심작 일정을 한 번에 요약 |
| 게시판 목록 | 카테고리, 최근 글, 구독 상태, 개념글 기준, 익명 허용 여부 표시 |
| 글 목록 | 제목보다 맥락 정보가 중요함. 말머리, 댓글, 추천, 조회, 작성자 신원 노출 |
| 글 상세 | 본문 가독성, 댓글 참여, 추천/리액션, 신고/차단 접근성 |
| 글쓰기 | 빠른 작성과 미디어/스티커 삽입의 균형 |
| 프로필 | 닉네임보다 오시, 배지, 대표 캐릭터, 활동을 강조 |
| 캐릭터 | 관리 화면은 복잡해도 런타임 노출은 가볍고 안전해야 함 |
| 캘린더 | 월간표보다 오늘/이번 주/내 관심작 요약이 중요 |
| 창작자 | 게시글 UX가 아니라 갤러리, 시리즈, 작품 감상 UX가 필요 |
| 구독/상점/의뢰 | 혜택, 가격, 토큰 사용처, 의뢰 범위, 환불 조건을 명확히 표시 |

### 8.3 모바일 고려

모바일에서는 Live2D, GNB, 글 목록, 댓글 입력창이 서로 공간을 침범하기 쉽다. 모바일은 데스크톱 축소판이 아니라 별도 우선순위가 필요하다.

- 글 목록과 댓글 입력을 최우선으로 둔다.
- Live2D는 접기/숨기기/말풍선 최소화 옵션을 제공한다.
- 알림과 글쓰기 버튼은 손가락 접근성을 고려한다.
- 캘린더는 월간표보다 리스트/오늘 요약을 우선한다.
- 창작물 뷰어는 세로 스크롤과 회차 이동에 집중한다.

## 9. 제품 의사결정 후보

아래 항목은 당장 모두 답을 내야 하는 숙제가 아니다. 제품 방향을 잡으면서 순서대로 판단하면 되는 선택지다.

1. 이 서비스의 1차 출시 정체성은 "커뮤니티 허브"로 고정할 것인가?
2. 창작자 트랙은 언제부터 메인 내비게이션에 올릴 것인가?
3. 웹툰/소설 유료 콘텐츠는 자체 창작물 중심인가, 외부 창작자 입점형인가?
4. 캐릭터 페르소나 챗은 메인 기능인가, 후순위 실험인가?
5. 캐릭터 슬롯, 시즌 캐릭터, 캐릭터 상점, 가챠는 어떤 결제 정책 안에서 운영할 것인가?
6. 캐릭터 의뢰 마켓은 창작자 트랙에 붙일 것인가, 캐릭터 영역에 독립시킬 것인가?
7. 토큰은 콘텐츠 구매용인가, 거래용 포인트까지 포함하는가?
8. 굿즈 거래는 열 것인가, 아니면 컬렉션/위시리스트까지만 할 것인가?
9. 인증 회원은 어떤 권한을 얻는가?
10. SNS 연동 가입과 회원정보 찾기는 어떤 우선순위로 넣을 것인가?
11. 다국어 허브는 국내 서비스 안정화 이후 별도 탭으로 실험할 것인가?
12. 성인 콘텐츠와 미성년자 캐릭터 안전 정책은 어디까지 엄격하게 둘 것인가?

## 10. 최종 정리

`씹덕`은 이미 커뮤니티의 기본 뼈대가 많이 구현되어 있다. 그러나 기획 관점에서 보면 아직 "완성된 제품"이라기보다 여러 성장축이 동시에 열린 상태다.

가장 현실적인 순서는 다음과 같다.

1. 커뮤니티 기본 루프와 운영 안전성을 마감한다.
2. 오시, 배지, 뉴스, 캘린더, Live2D를 덕질 허브로 묶는다.
3. 시즌패스, 토큰, 캐릭터 슬롯, 캐릭터 의뢰로 리텐션과 수익화 구조를 만든다.
4. 창작자 트랙과 웹툰/소설을 별도 UX로 확장한다.
5. 굿즈 컬렉션, 거래, 다국어, 캐릭터 페르소나 챗은 정책과 운영 역량이 갖춰진 뒤 실험한다.

핵심은 "무엇을 더 만들까"보다 "무엇을 먼저 제품답게 마감하고, 무엇을 후순위 실험으로 남길까"다.
